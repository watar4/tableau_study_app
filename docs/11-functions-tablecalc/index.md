## 1. 表計算とは（集計後に動く計算）

**表計算 (Table Calculation)** は、Tableau における 3 種類の計算 — 行レベル計算 / 集計計算 / 表計算 — のうち、**最後に評価される** 計算です。重要なのは「**ビューにすでに表示されている集計値** を入力として動く」という点です。

| 計算の種類 | 入力 | 例 |
|------------|------|-----|
| 行レベル計算 | データソースの 1 行 | `[fare] + [tips]` |
| 集計計算 | ビューの粒度で集計された値 | `SUM([fare]) / SUM([trip_total])` |
| 表計算 | ビュー上の **集計結果の集合** | `RUNNING_SUM(SUM([trip_total]))` |

そのため、表計算には次の特徴があります。

- **ビューの状態に依存** する。ディメンションを追加/削除すると結果が変わる。
- データベースには **追加クエリは飛ばず**、ビュー上で再計算される（軽い）。
- 「累計」「前年比」「順位」「移動平均」のような、**並びと位置関係** に基づく計算が得意。

## 2. 計算方向（アドレッシング / パーティショニング）

表計算で最も重要な概念が **計算方向** です。同じ式でも、どの方向に計算するかで結果がまったく変わります。

| 用語 | 役割 |
|------|------|
| **アドレッシング (Addressing)** | 計算が **動く方向**。「次へ」「前へ」の意味を持つフィールド。 |
| **パーティショニング (Partitioning)** | 計算を **リセットする境界**。サブグループの単位。 |

ビュー上のディメンションは、必ずアドレッシングかパーティショニングのいずれかに振り分けられます。

### 設定方法

表計算を右クリック →「次を使用して計算」を開きます。指定方法は 4 種類あります。

| 指定方法 | 意味 |
|----------|------|
| 表（横） | 行を超えて横方向に計算 |
| 表（下） | 列を超えて縦方向に計算 |
| ペイン（横/下） | 1 つの区画内だけで計算 |
| セル | 1 セル内 |
| **特定のディメンション** | アドレッシングに使うディメンションを明示的に選ぶ |

### 例

`年月` を列、`company` を行、`SUM(trip_total)` をテキストに置いたビューで、`RUNNING_SUM(SUM([trip_total]))` を `年月` で計算すると、

- **アドレッシング = 年月**: 横方向に月ごとに累積
- **パーティショニング = company**: 各会社で累計をリセット

となり、行ごと（=会社ごと）の累計売上推移が得られます。

::: warning 設計時に「方向」を必ず確認
表計算は、ディメンションの並び順や追加・削除で簡単に挙動が変わります。**特定のディメンションを指定** する設定にしておくと、ビューを再構成しても意図が崩れません。
:::

## 3. クイック表計算

代表的な表計算は **クイック表計算** としてメニューから 1 クリックで適用できます。フィールドを右クリック →「クイック表計算」から選択します。

| クイック表計算 | 内部の関数 | 用途 |
|-----------------|------------|------|
| **累計** | `RUNNING_SUM` | 期初からの累計売上 |
| **差** | `ZN(SUM(...)) - LOOKUP(ZN(SUM(...)), -1)` | 前期との差分 |
| **差の割合** | LOOKUP + 除算 | 前期比成長率 |
| **前年比成長率** | LOOKUP(...,-1) を年方向 | 対前年比 |
| **合計に対する割合** | `SUM(...) / TOTAL(SUM(...))` | 構成比 |
| **順位** | `RANK` | 売上ランキング |
| **パーセンタイル** | `RANK_PERCENTILE` | 上位 N% の位置 |
| **移動計算** | `WINDOW_AVG` 等 | 移動平均 |

## 4. WINDOW_SUM / WINDOW_AVG / WINDOW_MIN / WINDOW_MAX

**WINDOW_*** 系の関数は、指定範囲（ウィンドウ）内の集計値を返します。基本構文は次のとおりです。

```
WINDOW_SUM(<集計式>, <開始オフセット>, <終了オフセット>)
```

オフセットを省略すると、パーティション全体が対象になります。

```
WINDOW_AVG(SUM([trip_total]))
```

`-3` から `0` を指定すれば「**直前 3 つ + 現在**」の 4 区間移動平均です。

```
WINDOW_AVG(SUM([trip_total]), -3, 0)
```

| 関数 | 内容 |
|------|------|
| `WINDOW_SUM(expr, s, e)` | 範囲内の合計 |
| `WINDOW_AVG(expr, s, e)` | 範囲内の平均 |
| `WINDOW_MIN(expr, s, e)` | 範囲内の最小 |
| `WINDOW_MAX(expr, s, e)` | 範囲内の最大 |
| `WINDOW_COUNT(expr, s, e)` | 範囲内の件数 |
| `WINDOW_MEDIAN(expr, s, e)` | 範囲内の中央値 |
| `WINDOW_STDEV(expr, s, e)` | 範囲内の標準偏差 |

::: tip 構成比は WINDOW_SUM が定番
パーティション全体に対する各点の割合（構成比）を出す王道は次の式です。`TOTAL` 関数を使っても同等の結果が得られます。

```
SUM([trip_total]) / WINDOW_SUM(SUM([trip_total]))
```
:::

## 5. RUNNING_SUM / RUNNING_AVG

**RUNNING_*** は「**累積**」を返す関数で、計算方向の先頭から現在位置までの集計です。

| 関数 | 内容 |
|------|------|
| `RUNNING_SUM(expr)` | 累計 |
| `RUNNING_AVG(expr)` | 累積平均（移動平均ではない） |
| `RUNNING_MIN(expr)` | これまでの最小 |
| `RUNNING_MAX(expr)` | これまでの最大 |
| `RUNNING_COUNT(expr)` | 累積件数 |

```
RUNNING_SUM(SUM([trip_total]))
```

| 違い | RUNNING | WINDOW |
|------|---------|---------|
| 対象範囲 | 先頭〜現在 | 任意の範囲 |
| 用途 | 累計、これまで最大 | 移動平均、構成比 |

::: info RUNNING_AVG ≠ 移動平均
`RUNNING_AVG` は「**先頭から現在までの平均**」です。「直近 N 区間の平均」を出したい場合は `WINDOW_AVG(expr, -N+1, 0)` を使います。混同しがちなので注意します。
:::

## 6. LOOKUP / PREVIOUS_VALUE

### LOOKUP

`LOOKUP` は **オフセット指定で前後の値を取り出す** 関数です。前年比や前月差を作る基本部品です。

```
LOOKUP(<集計式>, <オフセット>)
```

```
LOOKUP(SUM([trip_total]), -1)
```

これは「ひとつ前の値」を返します。これを使えば前月比は次のように書けます。

```
SUM([trip_total]) / LOOKUP(SUM([trip_total]), -1) - 1
```

オフセット `0` は「現在の位置」、`1` は「次」、`-2` は「2 つ前」です。範囲外（先頭の `-1` など）では NULL が返ります。

### PREVIOUS_VALUE

`PREVIOUS_VALUE` は「**同じ式が直前のセルで返した値**」を取り出し、初回は引数の初期値を返します。再帰的な累積計算に使えます。

```
PREVIOUS_VALUE(0) + SUM([trip_total])
```

これは `RUNNING_SUM(SUM([trip_total]))` と等価です。`PREVIOUS_VALUE` は「累計だけでなく、過去の自分の値に依存する複雑なロジック」を組むときに真価を発揮します。

::: tip 前年比は LOOKUP の十八番
パーティショニングを「会社」、アドレッシングを「年」に設定して `LOOKUP(SUM([trip_total]), -1)` を使えば、各社の前年売上が取れます。それで現在を割れば前年比です。
:::

## 7. RANK 系（RANK / RANK_DENSE / RANK_UNIQUE / RANK_MODIFIED）

順位付け関数は 4 つあり、**同順位（タイ）の扱いが違います**。

| 関数 | 同順位の扱い | 結果例（値: 100, 90, 90, 80） |
|------|--------------|-------------------------------|
| `RANK` | 同順位、次は飛ばす（標準ランク） | 1, 2, 2, 4 |
| `RANK_DENSE` | 同順位、次は飛ばさない | 1, 2, 2, 3 |
| `RANK_MODIFIED` | 同順位は最大ランク | 1, 3, 3, 4 |
| `RANK_UNIQUE` | 同順位でも一意（並びで決まる） | 1, 2, 3, 4 |

第 2 引数で並び順を指定できます（既定は降順）。

```
RANK(SUM([trip_total]), 'desc')
```

```
RANK_DENSE(SUM([trip_total]))
```

::: info パーセンタイル順位
`RANK_PERCENTILE(expr)` は 0〜1 の範囲で、現在の値がパーティション内で「上位何 %」かを返します。「上位 10% のみハイライト」のような条件付け（IIF と組み合わせて色分け）で重宝します。
:::

## 8. INDEX / FIRST / LAST / SIZE

ビュー上の位置情報を返す関数群です。

| 関数 | 戻り値 |
|------|--------|
| `INDEX()` | 現在の位置（1 から始まる連番） |
| `FIRST()` | 先頭からのオフセット（先頭で 0、次が -1） |
| `LAST()` | 末尾からのオフセット（末尾で 0、その前が 1） |
| `SIZE()` | パーティションの行数 |

これらは引数なしの関数です。並び順や位置を使って絞り込みやハイライトを行う際に使います。

### TOP N フィルター（表計算による）

「会社別売上の上位 5 社だけ表示」は INDEX を使ったフィルターで実装できます。

```
INDEX() <= 5
```

このフィールドをフィルターに掛けてフィルターアクションを「フィルター」→「True」にすれば、上位 5 件だけ表示されます。`SUM(trip_total)` の降順で並べておくのがコツです。

### 先頭/末尾の判別

```
FIRST() = 0
```

これは「**現在の行が先頭かどうか**」を表す真偽値で、先頭行だけにラベルを付けるような演出に使います。

## 9. ネストされた表計算

表計算の入れ子もできます。例として「**累計の前年差**」は次のとおりです。

```
RUNNING_SUM(SUM([trip_total]))
  - LOOKUP(RUNNING_SUM(SUM([trip_total])), -12)
```

このとき内側と外側で計算方向を別に設定する必要があります。フィールドを右クリック →「表計算の編集」を開くと、「**入れ子になった計算**」のドロップダウンから内側/外側それぞれのアドレッシング・パーティショニングを設定できます。

::: warning ネスト表計算はビュー依存度が高い
入れ子になればなるほど、ディメンションを 1 つ追加しただけで結果が崩れやすくなります。**「特定のディメンション」モード** を使って明示的に方向を固定すると安定します。
:::

## 10. 表計算 vs LOD の判断基準

表計算と LOD は似た問題を解けることがあり、初学者がもっとも迷うポイントです。判断基準をまとめます。

| 観点 | 表計算 | LOD |
|------|--------|-----|
| 評価タイミング | ビュー描画後（クエリ後） | クエリの一部として（クエリ中） |
| データソースに負荷 | かけない（軽い） | かける（重い場合あり） |
| 順序依存 | あり（行の並びが意味を持つ） | なし |
| ビューの構造変更への耐性 | 弱い | 強い |
| 行レベルとの併用 | 不可（集計後だけ） | 可（FIXED の値は行レベルで使える） |
| 得意な問題 | 累計・前年比・順位・移動平均・構成比 | 顧客別初回購入・コホート・固定スカラー |

### 簡単な決め方

- **「順位・累計・前後比較」が必要** → 表計算
- **「行レベルで使うスカラー値」が必要** → LOD（特に FIXED）
- **「全体に対する割合」** → どちらでも可。表計算 (`WINDOW_SUM` / `TOTAL`) が軽い

LOD は次章で詳しく学びます。

## やってみよう

Chicago Taxi で表計算を実際に試します。`年月` を `DATETRUNC('month', [trip_start_timestamp])` で計算フィールドにしておくと便利です。

1. **準備**: `年月` を列、`company` を行、`SUM([trip_total])` をテキストに置きます（クロス集計表）。上位 5 社にフィルターしておくと見やすくなります。
2. **累計を作る**: `SUM([trip_total])` を右クリック →「クイック表計算」→「累計」を選択。表（横）方向に累積されているか確認します。
3. **計算方向を変える**: 右クリック →「次を使用して計算」→「**特定のディメンション**」を選び、`年月` だけにチェック。これで「会社ごとに月の累計」が出ます。
4. **前月差を作る**: 別シートで「クイック表計算」→「差」を選び、`LOOKUP(SUM(...), -1)` ベースの式に変わることを編集画面で確認します。
5. **移動平均**: 計算フィールド `WINDOW_AVG(SUM([trip_total]), -2, 0)` を作り、テキストに追加。3 区間移動平均と元の値を見比べます。
6. **構成比**: `SUM([trip_total]) / WINDOW_SUM(SUM([trip_total]))` を作って、書式設定でパーセント表示にします。月ごとの会社シェアが出ます。
7. **TOP 5 フィルター**: `INDEX() <= 5` を計算フィールドに作成し、フィルターに掛けて True を選択。元のフィルターを外すと、表計算ベースの動的トップ 5 が動きます。
8. **順位**: `RANK_DENSE(SUM([trip_total]))` を列に置き、ランキングテーブルを作ります。タイの扱いを RANK と比較します。

## まとめ

- 表計算は **集計後のビュー** に対して動く、最も最後に評価される計算。
- **アドレッシング（方向）** と **パーティショニング（区切り）** をきちんと指定することで、意図した方向に計算が走る。
- **WINDOW_***、**RUNNING_***、**LOOKUP**、**RANK** 系、**INDEX/FIRST/LAST/SIZE** が主要ファミリー。
- クイック表計算は雛形として優秀。式を編集して仕組みを学ぶのが近道。
- 表計算は **データソースに負荷を掛けず軽い** が、ビューの構造変更に弱い。
- 「行レベルで使えるスカラーが欲しい」「順序非依存に固定値が欲しい」場合は **LOD** を選ぶ。
