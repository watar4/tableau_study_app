## 1. 計算フィールドとは

**計算フィールド (Calculated Field)** とは、元のデータには存在しないフィールドを、既存のフィールドや関数を使って Tableau 上で新しく作る仕組みです。Excel における「数式列」に近い概念ですが、Tableau ではこれをデータソース単位で定義し、複数のワークシートから再利用できます。

Chicago Taxi のデータには `fare`（料金）と `trip_miles`（距離）はありますが、「1マイルあたりの料金 (= 距離単価)」は存在しません。このような **派生指標** を作るのが計算フィールドの典型的な用途です。

| 用途 | 例 |
|------|----|
| 比率・単価の計算 | `[fare] / [trip_miles]`（マイル単価）、`[tips] / [fare]`（チップ率） |
| カテゴリの再分類 | `IF [trip_total] >= 50 THEN "高額" ELSE "通常" END` |
| 文字列の加工 | `LEFT([company], 4)` で会社コードを抽出 |
| 日付計算 | `DATEDIFF('day', [trip_start_timestamp], TODAY())` |
| 集計の組み合わせ | `SUM([tips]) / SUM([fare])`（全体のチップ率） |

### 計算フィールドの作成手順

1. データペインの空白部分を右クリック → 「**計算フィールドの作成**」（または、メニュー「分析」 → 「計算フィールドの作成」）
2. 上部に **計算フィールド名** を入力
3. 中央のエディタに **計算式** を入力
4. 左下に「計算は有効です」と表示されれば OK。「OK」をクリックして保存

![計算フィールドの作成メニュー](/images/06-calc-basics/create-calc.png)

::: tip フィールド名は分かりやすく
ダッシュボードを他人に渡すことを考えると、「テスト1」「計算3」のような名前は避け、`チップ率` `マイル単価 (USD)` のように単位と意味が読み取れる名前にしましょう。Tableau のフィールド名は日本語でも問題なく動作します。
:::

## 2. 計算エディタの使い方

計算エディタは単なるテキスト入力欄ではなく、**補完・関数リファレンス・構文チェック** が一体になった補助 UI を備えています。

![計算エディタと右側の関数リファレンス](/images/06-calc-basics/calc-editor.png)

### 主な機能

| 機能 | 操作 |
|------|------|
| **フィールド名の補完** | `[` を入力するとデータペインのフィールド一覧が候補表示される |
| **関数名の補完** | 関数の頭文字を入力 → Tab キーで補完 |
| **関数リファレンス** | エディタ右側の「▶」をクリックすると、関数カテゴリ一覧 → 関数を選ぶと引数・戻り型・使用例が表示される |
| **構文チェック** | 入力中にリアルタイムで「計算は有効です」 / エラーメッセージを表示 |
| **エラー位置の表示** | エラーがある場合、エディタ内で該当箇所が赤くハイライトされる |

### 関数の探し方

関数名を覚えていなくても、関数リファレンスのカテゴリ（数値・文字列・日付・集計・論理…）から絞り込めます。関数をダブルクリックすればその場で挿入され、引数のひな形が入ります。

::: info `[ ]` の意味
フィールド名はそのままだと予約語と区別がつかないため、原則として角括弧 `[ ]` で囲みます。フィールド名にスペースや日本語、特殊文字が含まれる場合は必須です。`[trip_total]` のように英数アンダースコアだけなら角括弧を省略できる場合もありますが、常に付ける運用が安全です。
:::

## 3. 演算子と優先順位

計算フィールドでは標準的な四則演算と比較演算子が使えます。

### 算術演算子

| 演算子 | 意味 | 例 |
|--------|------|----|
| `+` | 加算（文字列なら連結） | `[fare] + [tips]` |
| `-` | 減算 | `[trip_total] - [fare]` |
| `*` | 乗算 | `[trip_miles] * 1.60934` |
| `/` | 除算（結果は実数） | `[tips] / [fare]` |
| `%` | 剰余 | `[trip_seconds] % 60` |
| `^` | べき乗 | `[trip_miles] ^ 2` |

### 比較・論理演算子

| 演算子 | 意味 |
|--------|------|
| `=` または `==` | 等しい |
| `<>` または `!=` | 等しくない |
| `>` `<` `>=` `<=` | 大小比較 |
| `AND` `OR` `NOT` | 論理演算 |

### 優先順位

数学と同じく、以下の順に評価されます。括弧 `( )` で明示するのが最も確実です。

1. `( )` 括弧
2. `^` べき乗
3. `*` `/` `%`
4. `+` `-`
5. `=` `<>` `<` `>` `<=` `>=`
6. `NOT`
7. `AND`
8. `OR`

```
// 括弧で明示すべき例
([fare] + [tips]) / [trip_miles]   // 合計を距離で割る
[fare] + [tips] / [trip_miles]     // tips/miles だけ先に評価されてしまう
```

::: warning 整数同士の除算に注意
他言語と異なり、Tableau では整数 / 整数も実数を返します（例: `5 / 2 = 2.5`）。明示的に整数除算したい場合は `DIV(5, 2)` を使います。
:::

## 4. データ型と暗黙の型変換

Tableau のフィールドは以下の型を持ちます。

| 型 | アイコン | 例 |
|----|---------|----|
| 数値（整数・実数） | `#` | `trip_seconds`、`trip_total` |
| 文字列 | `Abc` | `payment_type`、`company` |
| 日付 / 日時 | カレンダー | `trip_start_timestamp` |
| ブール | `T\|F` | `IS NULL` の結果など |
| 地理的役割 | 地球儀 | `pickup_centroid_latitude` |

### 暗黙の型変換

異なる型同士を演算した場合、Tableau は自動的にいくつかの型変換を行いますが、できないものもあります。

```
// OK: 整数 + 実数 → 実数
[trip_seconds] + [trip_miles]

// NG: 文字列 + 数値（エラー）
"運賃: " + [fare]

// OK: 文字列同士の連結
"運賃: " + STR([fare])
```

### よくある落とし穴

- 数値を文字列に連結する際は `STR()` で必ず明示的に変換が必要です
- CSV から読み込んだ「数字に見える列」が文字列として認識されていることがあります。データソース画面で型アイコンを確認しましょう
- 日付が文字列になっている場合は `DATEPARSE()` で変換します（07章で扱います）

::: tip 型のヒントは赤い線
計算エディタで型不一致が起きていると、該当箇所に赤いアンダーラインが表示されます。マウスを乗せるとエラー内容が読めます。
:::

## 5. null の発生源と対処

実データには **null（値なし）** が頻繁に登場します。null をそのまま放置すると、集計から除外されたり、計算結果全体が null になったりします。

### null の発生源

- 元データに値が入っていない（例: `tips` が空欄）
- 0 除算の結果（`[fare] / 0` → null）
- 型変換に失敗した場合（`INT("abc")` → null）
- 結合（JOIN）でマッチしなかった側のフィールド
- フィルターやセットで除外されたデータ

### null 関連の関数

| 関数 | 用途 | 例 |
|------|------|----|
| `ISNULL(値)` | null なら true | `ISNULL([tips])` |
| `IFNULL(値, 代替値)` | null なら代替値を返す | `IFNULL([tips], 0)` |
| `ZN(値)` | null を 0 に変換（Zero if Null） | `ZN([tips])` |
| `IIF(条件, A, B, [unknown])` | 三項演算子。条件が null のとき第4引数を返す | `IIF([tips] > 0, "有", "無", "不明")` |

### 使い分け

```
// 数値型のフィールドで null を 0 として集計したい → ZN が最短
SUM(ZN([tips]))

// 文字列など 0 以外の代替値にしたい → IFNULL
IFNULL([payment_type], "未指定")

// 条件分岐の中で「null かどうか」を判定したい → ISNULL
IF ISNULL([tips]) THEN "チップなし" ELSE "チップあり" END
```

::: warning 0 除算は null になる
`[fare] / [trip_miles]` で `trip_miles = 0` の行があると結果は null です。エラーにはなりませんが、平均などの集計結果が変わってきます。`IIF([trip_miles] = 0, NULL, [fare] / [trip_miles])` のように明示するか、`trip_miles > 0` でフィルターを掛けるのが安全です。
:::

## 6. 行レベル計算 vs 集計計算

計算フィールドは大きく 2 種類に分けられます。両者の違いを理解することが、Tableau の計算で最初に乗り越えるべき山です。

### 行レベル計算 (Row-Level Calculation)

各行に対して 1 行ずつ評価され、結果も「行のフィールド」として扱われます。元データに新しい列を足すイメージです。

```
// 1 行ごとに料金と距離から単価を計算
[fare] / [trip_miles]
```

このフィールドはデータペインで「メジャー」または「ディメンション」として配置でき、ビューで集計するときに `SUM()` `AVG()` を被せます。

### 集計計算 (Aggregate Calculation)

`SUM()` `AVG()` `COUNT()` などの集計関数を内部で使う計算です。ビューの粒度に応じて評価され、結果も集計値として扱われます。

```
// 全体合計に対するチップ率
SUM([tips]) / SUM([fare])
```

これは「行ごとに `tips / fare` を出してから平均する」のではなく、「全体の `tips` 合計を全体の `fare` 合計で割る」結果になります。比率指標ではこちらが正しいことが多いです。

### よくある混在エラー

行レベルと集計を一つの式で **混ぜると** エラーになります。

```
// NG: 行レベル [tips] と 集計 SUM([fare]) を混ぜている
[tips] / SUM([fare])

// OK: 両方とも集計
SUM([tips]) / SUM([fare])
```

### ATTR の挙動

`ATTR(フィールド)` は「ビューの粒度内で値が一意なら、その値を返す。複数あれば `*` を返す」という特殊な集計です。ディメンションをメジャーのように扱いたいときに使用します。

```
ATTR([payment_type])
```

ビューに `company` を行に置いた状態でこの計算をツールヒントに乗せると、各会社の支払方法が 1 種類なら値が、複数あれば `*` が表示されます。

::: info 区別の見分け方
行レベル計算は集計関数を含みません。集計計算は **必ず** 何らかの集計関数（`SUM` `AVG` `COUNT` `MIN` `MAX` `ATTR` など）を含みます。一つの式の中ですべて集計するか、すべて行レベルにするか、どちらかに統一しましょう。
:::

## 7. コメント記法

計算式が複雑になると、後から読み返したときに意図が分かりにくくなります。コメントを書く習慣をつけましょう。

### 行コメント `//`

```
// マイルあたりの料金（マイル単価）
[fare] / [trip_miles]
```

### ブロックコメント `/* */`

```
/*
  チップ率の計算
  - fare = 0 の行は除外（0 除算回避）
  - 結果は 0.0 〜 1.0 の小数
*/
IIF([fare] = 0, NULL, [tips] / [fare])
```

::: tip コメントで残すべき情報
- なぜこの計算が必要なのか（業務的な意図）
- 端数処理や除外条件の理由
- 関連するパラメーターやフィルター
- 想定される結果の範囲（例: 0〜1 の割合）
:::

## やってみよう

Chicago Taxi のデータを使って、計算フィールドの基本を実際に作ってみましょう。

1. **データに接続**
   - `chicago_taxi_trips.hyper` に接続し、新規ワークシートを開きます。
2. **マイル単価（行レベル計算）を作る**
   - データペインで右クリック → 「計算フィールドの作成」
   - 名前: `マイル単価 (USD)`
   - 式:
     ```
     // 1 マイルあたりの料金（fare ベース）
     IIF([trip_miles] = 0, NULL, [fare] / [trip_miles])
     ```
   - 行に `company`、列に `AVG([マイル単価 (USD)])` をドラッグして、会社別の平均単価を確認します。
3. **チップ率（集計計算）を作る**
   - 名前: `チップ率`
   - 式:
     ```
     SUM([tips]) / SUM([fare])
     ```
   - これを `payment_type` 別に表示し、Cash と Credit Card で大きな差が出ることを確認します。
4. **料金帯バンド（条件式）を作る**
   - 名前: `料金帯`
   - 式:
     ```
     IF [trip_total] >= 50 THEN "高額"
     ELSEIF [trip_total] >= 20 THEN "中額"
     ELSE "通常"
     END
     ```
   - これをディメンションとして列に置き、行に `COUNT([trip_id])` を置いて分布を見ます。
5. **null 処理を試す**
   - `SUM([tips])` のビューを作り、その後 `SUM(ZN([tips]))` に書き換えて結果が変わるかを確認します（`tips` が null の行が含まれていれば差が出ます）。
6. **コメントを付ける**
   - 上で作った計算フィールドそれぞれに、`//` 形式のコメントで「何を計算しているか」「除外条件」を書き残します。
7. **エラーを意図的に出す**
   - `[tips] / SUM([fare])` のような式を入力し、行レベルと集計を混ぜたエラーメッセージを観察します。
8. **既存計算の再利用**
   - 別のワークシートで `[マイル単価 (USD)]` を呼び出し、データソース全体で再利用できることを確認します。

## まとめ

- **計算フィールド** は、既存フィールドと関数を組み合わせて派生指標を作る仕組みで、データソース全体で再利用できます。
- 演算子には算術・比較・論理があり、優先順位を意識して **括弧で明示** するのが安全です。Tableau の `/` は実数除算で、整数除算には `DIV()` を使います。
- 異なる型同士の演算は基本的にエラーになります。文字列に数値を連結する際は `STR()` で明示的に変換します。
- **null** は 0 除算・型変換失敗・JOIN 不一致などから発生します。`ZN` `IFNULL` `ISNULL` を場面に応じて使い分けます。
- **行レベル計算** と **集計計算** は混在させられません。比率指標は集計後に割るのが一般的です。
- 計算式が複雑になる前に `//` や `/* */` でコメントを残し、意図と前提条件を明文化しましょう。
