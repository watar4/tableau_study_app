## 1. お題: 「シカゴのタクシー利用ダッシュボード」

本章では、これまで学んできた要素を組み合わせて 1 本のダッシュボードを完成させます。お題は「**シカゴ市の 2023 年タクシー利用状況を俯瞰するダッシュボード**」です。

### 仮ペルソナと閲覧シナリオ

| 項目 | 内容 |
|------|------|
| **ペルソナ** | シカゴ市交通局の分析担当者（30 代、Tableau 中級） |
| **目的** | 2023 年のタクシー利用全体像を把握し、政策提案の素材にしたい |
| **閲覧頻度** | 月 1 回程度、四半期レビュー前にもチェック |
| **使う画面** | デスクトップブラウザ（1366 × 768 〜 1920 × 1080） |
| **アクション** | 数字を見て「気になる地域 / 会社 / 時期」を発見したら、もう一段深堀りしたい |

### 一目で得たい情報

- 年間の総売上・総乗車回数・1 乗車あたり平均料金
- 月次の利用トレンド（季節性はあるか）
- 会社別のシェア（特定の会社に集中しているか）
- 支払方法のシェア（キャッシュレス化の進捗）
- 乗車エリアの分布（どこから乗る人が多いか）

---

## 2. 要件定義（誰が・何を知りたいか）

ダッシュボード制作は「**まず作る**」のではなく、**要件を言語化する**ところから始めます。以下のような要件シートを書き起こすと、後工程の判断が楽になります。

| 項目 | 例 |
|------|-----|
| **誰が見るか** | シカゴ市交通局のアナリスト |
| **何を知りたいか** | 2023 年のタクシー需要の全体像と特徴的なエリア・会社 |
| **何を判断するか** | 政策レポートに使う素材として、深堀すべき仮説を見つける |
| **見せ方の制約** | 1 画面（縦スクロールなし）に収める |
| **更新頻度** | 月次（手動更新でも可） |
| **対話性** | 月選択・支払方法選択フィルターは必須。会社選択は任意 |
| **公開先** | Tableau Public |

::: tip 「3 秒テスト」と「30 秒テスト」を意識
ダッシュボードを開いて 3 秒で「これは何の画面か」、30 秒で「主要なメッセージは何か」が伝わる構成を目指しましょう。
:::

---

## 3. データ理解（列・粒度・期間）

`chicago_taxi_trips.hyper` の構造を確認します。

### 主要な列

| 列名 | 型 | 説明 |
|------|----|----|
| `trip_id` | TEXT | 乗車ごとのユニーク ID |
| `taxi_id` | TEXT | タクシー車両 ID |
| `trip_start_timestamp` | TIMESTAMP | 乗車開始日時 |
| `trip_end_timestamp` | TIMESTAMP | 乗車終了日時 |
| `trip_seconds` | BIG_INT | 乗車時間（秒） |
| `trip_miles` | DOUBLE | 走行距離（マイル） |
| `fare` | DOUBLE | 基本料金 |
| `tips` | DOUBLE | チップ |
| `tolls` | DOUBLE | 通行料 |
| `extras` | DOUBLE | 追加料金 |
| `trip_total` | DOUBLE | 合計金額 |
| `payment_type` | TEXT | "Cash" / "Credit Card" / "Mobile" など |
| `company` | TEXT | タクシー会社（36 社） |
| `pickup_community_area` | BIG_INT | 乗車エリア（コミュニティエリア番号） |
| `dropoff_community_area` | BIG_INT | 降車エリア |
| `pickup_centroid_latitude` | DOUBLE | 乗車緯度 |
| `pickup_centroid_longitude` | DOUBLE | 乗車経度 |
| `dropoff_centroid_latitude` | DOUBLE | 降車緯度 |
| `dropoff_centroid_longitude` | DOUBLE | 降車経度 |

### 粒度・期間・件数

- **粒度**: 1 行 = 1 乗車（`trip_id` がユニーク）
- **期間**: 2023 年通年（環境によって微妙に範囲が異なる場合あり）
- **件数**: 1,000,000 行（百万行のサンプル）

### 確認・前処理

1. データソースタブで型を確認（緯度経度が地理データ扱いになっているか）
2. `pickup_community_area` を「ディメンション」に変換
3. 必要に応じて `trip_start_timestamp` から「年」「月」「曜日」「時間」を切り出して使う
4. 計算フィールド `平均料金 = SUM([trip_total]) / COUNT([trip_id])` を作成

::: warning データの欠損
公開データのため、`trip_miles = 0` や `trip_total = 0` のレコードが混在することがあります。極端な外れ値（>100 マイルなど）も観察されます。フィルターまたは計算で「異常値」を除外する設計を検討してください。
:::

## 4. シート設計（KPI / 推移 / 構成 / 地理 / 詳細）

ダッシュボードに載せる前に、シートを「**役割ごと**」に設計します。1 シート = 1 メッセージが原則です。

### シート構成案

| # | シート役割 | チャート種類 | フィールド構成 |
|---|------------|--------------|----------------|
| ① | KPI: 総売上 | 大きな数字 (BAN) | `SUM([trip_total])` |
| ② | KPI: 総乗車回数 | 大きな数字 | `COUNT([trip_id])` |
| ③ | KPI: 平均距離 | 大きな数字 | `AVG([trip_miles])` |
| ④ | KPI: 平均料金 | 大きな数字 | `SUM([trip_total]) / COUNT([trip_id])` |
| ⑤ | 推移: 月次トレンド | 折れ線 | 月（連続）× `SUM([trip_total])` |
| ⑥ | 構成: 会社別シェア | 水平棒（TOP10） | `company` × `SUM([trip_total])` |
| ⑦ | 構成: 支払方法別 | 円グラフ または 棒 | `payment_type` × `SUM([trip_total])` |
| ⑧ | 地理: 乗車地ヒートマップ | マップ（密度） | `pickup_centroid_latitude/longitude` |
| ⑨ | 詳細: 上位会社の明細 | テキスト表 | 会社/月/売上/平均料金 |

### KPI カードの作り方（おさらい）

1. テキストシェルフにメジャーを 1 つだけ置く
2. マークタイプは「テキスト」
3. フォントを 36pt〜48pt 程度に拡大
4. シートのタイトルに指標名を書く（例: 「総売上 (2023)」）

### マップの作り方（おさらい）

1. `pickup_centroid_latitude` を「行」、`pickup_centroid_longitude` を「列」にダブルクリック（緯度経度として認識されているか確認）
2. マークタイプ「密度（ヒートマップ）」を選択
3. 色を変えて視認性を上げる

## 5. ダッシュボード組み立て

シートがそろったら、ダッシュボードに配置します。タイル + レイアウトコンテナで骨格を作る方針で進めます。

### 推奨レイアウト

```
[ タイトル ]
[ ① 総売上 ][ ② 乗車回数 ][ ③ 平均距離 ][ ④ 平均料金 ]   ← 水平コンテナ (KPI 行)
[ ⑤ 月次トレンド (折れ線)                                ]   ← 全幅
[ ⑥ 会社別 TOP10  ][ ⑦ 支払方法別  ][ ⑧ 乗車地マップ ]   ← 水平コンテナ
[ ⑨ 上位会社の明細表（折りたたみ可）                     ]
```

### サイズと配置

| 領域 | 推奨サイズ目安 |
|------|----------------|
| ダッシュボード全体 | 1366 × 800（固定） |
| タイトル行 | 高さ 60〜80 px |
| KPI 行 | 高さ 100〜120 px |
| 月次トレンド | 高さ 200 px |
| 中段（3 シート横並び） | 高さ 250〜300 px |
| 明細表 | 高さ 150 px（または非表示でアクション経由で展開） |

### 組み立てのコツ

- 最初に「**垂直コンテナ**」を全面に敷き、その中に各行の「**水平コンテナ**」を入れる
- KPI 行はテキストを大きく、背景に薄いグレーを敷いて見出しを締める
- 凡例は重複させず、色のルールはダッシュボード全体で統一
- 「フィルター」は左サイドに**垂直に並べる**か、上部に**コンパクトに置く**

### 対話性

- 月次トレンドのマーク選択 → 他シートをその月にフィルター（フィルターアクション）
- 会社別棒グラフのマーク選択 → ハイライトアクションで他シートのその会社を強調
- 「指標切替」パラメーターで KPI の意味づけを変えるのは応用課題

## 6. レビュー観点チェックリスト

公開前のセルフレビューに使うチェックリストです。

### 視覚デザイン

- [ ] カラーパレットがバラバラになっていないか
- [ ] 同じディメンションは全シートで同じ色に揃っているか
- [ ] 数字の桁区切り（カンマ）と単位（$、回、マイル）は明記されているか
- [ ] フォントサイズに階層がついているか（タイトル > KPI > 軸 > 注釈）
- [ ] 背景・グリッド線が「見せたい情報」を邪魔していないか

### 情報設計

- [ ] タイトルだけで「何の画面か」が分かるか
- [ ] KPI に対応する期間が明示されているか
- [ ] 軸ラベル・凡例ラベルが分かりやすいか
- [ ] ツールヒントに必要な補足情報が入っているか

### 対話性

- [ ] フィルターは関連するシートに正しく効いているか
- [ ] フィルターアクションを解除すると初期状態に戻るか
- [ ] フィルターのデフォルト値は「全期間」「全種類」になっているか
- [ ] 想定外のクリックでダッシュボードが壊れないか

### アクセシビリティ

- [ ] 赤緑だけで意味を区別していないか
- [ ] 背景と文字のコントラストが十分か
- [ ] 主要メッセージが色だけでなく文字でも伝わるか

### データ品質

- [ ] 異常値（trip_miles=0、trip_total<0 など）が除外されているか
- [ ] 月次トレンドに不自然な凹みがないか（データ欠損の可能性）
- [ ] 合計値が他資料と矛盾していないか

### 公開準備

- [ ] 機微情報が含まれていないか
- [ ] データ出典の表記が入っているか
- [ ] 未使用シートを削除したか
- [ ] ワークブック名、シート名が公開向けに整っているか

## 7. 公開して終了

最終ステップとして Tableau Public に公開します。17 章のおさらいになります。

1. メニュー「**サーバー**」 → 「**Tableau Public**」 → 「**Tableau Public にサインイン**」でアカウントへサインイン
2. 「**ワークブックの保存**」を選び、ワークブック名（例: `Chicago Taxi 2023 Overview`）を入力
3. アップロード完了後、自動で開く公開ページを確認
4. 「**シェア**」ボタンから URL をコピーして、自分のブログや SNS で共有
5. 必要に応じて埋め込みコードを取得し、Web サイトに iframe で埋め込む

::: tip ポートフォリオに育てる
Tableau Public のプロフィールには、作ったダッシュボードが作品集として並びます。これを公開ポートフォリオとして使い、データビジュアライズの実績を蓄積している人もたくさんいます。
:::

## まとめ

- ダッシュボード制作は「**要件定義 → データ理解 → シート設計 → 組み立て → レビュー → 公開**」の順で進めるのが基本です。
- 1 シート = 1 メッセージ の原則で、KPI / 推移 / 構成 / 地理 / 詳細 を役割ごとに作り分けましょう。
- レイアウトは「垂直コンテナ + 水平コンテナ」の入れ子で骨格を作り、固定サイズで安定させます。
- 対話性はフィルターアクションとハイライトアクションを軸に、シンプルかつ予測可能に設計しましょう。
- 公開前にはレビューチェックリストを必ず通し、機微情報・出典・命名を整えます。
- Tableau Public はそのまま作品ポートフォリオになるので、継続的に積み上げると学習資産になります。
