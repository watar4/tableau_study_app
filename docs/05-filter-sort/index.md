## 1. 集計の基本

Tableau のメジャーは、ビューに置いた瞬間に自動で **集計関数** が適用されます。代表的なものを押さえましょう。

| 関数 | 意味 | Chicago Taxi での例 |
|------|------|-------------------|
| `SUM` | 合計 | `SUM(trip_total)` で会社別売上 |
| `AVG` | 平均 | `AVG(trip_miles)` で平均距離 |
| `MIN` / `MAX` | 最小 / 最大 | `MAX(trip_total)` で最高運賃 |
| `COUNT` | 件数（NULL 除く） | `COUNT(trip_id)` で乗車件数 |
| `COUNTD` | ユニーク件数 | `COUNTD(taxi_id)` で稼働タクシー数 |
| `MEDIAN` | 中央値 | `MEDIAN(trip_total)` で外れ値の影響を抑えた中心値 |

### 集計の切替

メジャーピルを右クリック → 「メジャー」 → 集計関数を選択、で切り替えられます。たとえば `SUM(trip_total)` を `AVG` にすれば「平均運賃」になります。

::: tip COUNT と COUNTD の違い
`COUNT(trip_id)` は **NULL でない trip_id の件数** を返し、`COUNTD(taxi_id)` は **重複を除いた taxi_id の種類数** を返します。「乗車件数」を出したいときは `COUNT(trip_id)`、「稼働した実車両数」を出したいときは `COUNTD(taxi_id)` を選びます。
:::

::: warning COUNTD はライブだと重い
`COUNTD` は DB 側で重い処理になりがちです。大規模 DB へのライブ接続では極端に遅くなる場面があり、抽出 (Hyper) で動かすほうが現実的です。
:::

## 2. フィルターの評価順序

Tableau のフィルターは **6 段階** で評価され、上位のものほど先に効きます。これを理解していないと「フィルターを変えても結果が変わらない」「合計が合わない」といったトラブルの原因になります。

```
[ソース DB]
   ↓
1. 抽出フィルター            ← .hyper 生成時に行を絞る
   ↓
2. データソースフィルター     ← 接続全体に適用される (公開時にも保存される)
   ↓
3. コンテキストフィルター      ← 「コンテキストに追加」したディメンションフィルター
   ↓
4. ディメンションフィルター   ← フィルターシェルフ上の通常フィルター
   ↓
5. メジャーフィルター         ← 集計後の値で絞り込み (例: SUM(trip_total) > 1000)
   ↓
6. 表計算フィルター           ← 表計算 (LOOKUP, WINDOW_*, RANK 等) の結果でフィルター
   ↓
[ビュー描画]
```

### 上位 N との関係

上位 N フィルター（後述）は **ディメンションフィルター** の一種ですが、**集計に基づくランキング** を内部で使います。そのため、上位 N の評価対象を絞り込みたい場合は **コンテキストフィルター** が役立ちます（次節）。

![フィルター評価順のレイヤー図](/images/05-filter-sort/filter-order.png)

## 3. ディメンションフィルター / メジャーフィルター

フィルターシェルフ上のフィルターは、**何で絞るか** によって 2 種類に大別されます。

| 種類 | 例 | タイミング |
|------|----|-----------|
| **ディメンションフィルター** | `payment_type = 'Credit Card'`、`company` 指定 | 集計の **前** |
| **メジャーフィルター** | `SUM(trip_total) > 1000` | 集計の **後** |

### ディメンションフィルターの 4 タブ

ディメンションをフィルターシェルフにドラッグすると、設定ダイアログに 4 つのタブが現れます。

| タブ | 目的 |
|------|------|
| **全般** | 値を直接チェックして選ぶ |
| **ワイルドカード** | `*Credit*` のような文字パターン |
| **条件** | `SUM(trip_total) > 5000` のような集計条件 |
| **上位** | 上位 / 下位 N（後述） |

### メジャーフィルターの落とし穴

`SUM(trip_total) > 1000` のようなメジャーフィルターは「**集計後** の値」で評価されます。会社別ビューでは「会社ごとの SUM が 1000 超」を、月別ビューでは「月ごとの SUM が 1000 超」を意味し、**粒度が変わると挙動も変わる** 点に注意します。

## 4. コンテキストフィルター

コンテキストフィルターは **ディメンションフィルターの中で「先に評価する」と宣言したもの** です。フィルターシェルフのピルを右クリック → 「コンテキストに追加」で設定し、ピルが **灰色** に変わります。

### 主な使いどころ

1. **上位 N の対象を絞る**: たとえば「`payment_type = 'Credit Card'` のうち、売上トップ 5 の `company`」を出したい場合、まず `payment_type` をコンテキストに昇格させて、上位 N より先に評価させる
2. **複雑なフィルター構成の整理**: 「絶対先に効く前提条件」を視覚的に区別する
3. **パフォーマンス**: コンテキストはセッション中に **一時テーブル** として実体化される場合があり、後続のフィルター・計算で再利用されます

::: info パフォーマンスの過信は禁物
「コンテキストにすれば速い」は古いガイドの記述で、Hyper 時代の現在は **必ずしも当てはまりません**。一時テーブル作成のオーバーヘッドが逆効果になる場合もあるため、まずは正確性のために使う、と捉えるのが安全です。
:::

![コンテキストに追加されたフィルター（灰色）](/images/05-filter-sort/context-filter.png)

## 5. 上位 N フィルター

「売上トップ 5 の会社だけ表示」のような **ランキング絞り込み** を実現するのが上位 N フィルターです。

### 設定方法

1. `company` をフィルターシェルフへ
2. 「上位」タブを開く
3. 「フィールド指定」 → 「上位」 → 「5」 → 評価する集計を選ぶ（例: `SUM(trip_total)`）

### 値の指定方法

| 指定方法 | 用途 |
|----------|------|
| **固定値** | 「常にトップ 5」 |
| **パラメーター** | ユーザーがダッシュボード上で N を変えられる |
| **計算** | 動的に N を決めたい場合（例: 会社総数の 10%） |

### パラメーター連動の例

```
[N パラメーター]
  → データペインで「パラメーターの作成」
  → データ型: 整数、現在値: 5、許容値: 範囲 (1〜20)

[上位フィルター]
  → 上位 N の値に [N パラメーター] を指定
```

ダッシュボードでパラメーターコントロールを表示すれば、利用者がスライダで「トップ何社まで見たいか」を変えられます。

::: warning 上位 N とディメンションフィルターの併用
上位 N と他のディメンションフィルターを併用すると、「上位 N は何の中の上位なのか」が曖昧になります。`payment_type` で `Credit Card` に絞った中での上位 5 にしたい場合は、`payment_type` フィルターを **コンテキスト** に昇格させる必要があります。
:::

## 6. 並べ替え

並べ替えは見た目を整える以上に **可読性** を大きく左右します。

### 並べ替えの種類

| 種類 | 動作 | 用途 |
|------|------|------|
| **手動** | ドラッグでカテゴリの順序を直接指定 | 業務固有の順序（例: 「Cash → Credit Card → Mobile」など） |
| **データソース順** | DB / ファイル上の出現順 | 既に整っているデータ |
| **アルファベット** | 文字列順 | 並べ方の客観性が必要なとき |
| **フィールド (集計) 順** | 集計値で並べる（例: `SUM(trip_total)` 降順） | ランキング型のビュー |

### ネスト並べ替えの落とし穴

行に **2 つ以上のディメンション** を置いた場合、並べ替えは **直近のディメンションのスコープ内** で適用されます。たとえば行が `payment_type` → `company` の順なら、「会社の売上順」は **各 `payment_type` の中での順序** であって、全体での順序ではありません。

::: tip 全体での順序にしたいなら
「全体のトップ 5 を表示しつつ、内訳として `payment_type` も見せたい」場合は、ネストせずに **上位 N + 詳細シェルフ** や **`company` を列・`payment_type` を色** のような構成に組み替えるほうが直感的です。
:::

![ネスト並べ替え（payment_type の中での company 順）](/images/05-filter-sort/nested-sort.png)

## 7. グループ・セット・ビン

カテゴリやメジャーを **再分類** するための 3 つの道具です。

| 道具 | 概要 | Chicago Taxi での例 |
|------|------|-------------------|
| **グループ (Group)** | 複数の値を 1 つにまとめた **静的な分類** | 似た名前の `company` を「○○系列」にまとめる |
| **セット (Set)** | 条件に合う **メンバーの集合**（動的 or 固定） | 「累計売上トップ 10 会社」のセット |
| **ビン (Bin)** | メジャーを **等幅の階級** に区切る | `trip_miles` を 1 マイル刻みに分けてヒストグラム |

### グループの作成

データペインで `company` を右クリック → 「作成」 → 「グループ」。複数値を選択して「グループ」ボタンで結合します。あとから編集可能で、ビューでは元フィールドとは別の派生フィールドとして使えます。

### セットの作成

「静的セット」と「動的（条件 / 上位）セット」があります。

```
[条件セット] company について
  SUM(trip_total) >= 100000
```

セットは **IN / OUT のブール** として扱えるので、フィルター・色・計算で「対象 / 非対象」を切り分ける用途に強力です。

### ビンの作成

メジャー（例: `trip_miles`）を右クリック → 「作成」 → 「ビン」 → サイズを指定（例: 1）。これをディメンションとして使うと、ヒストグラムの軸になります。

::: info グループ vs セット
- **グループ**: 値を **再ラベル** する（多 → 1 の写像）
- **セット**: 値を **IN/OUT で 2 値化** する

混同しがちですが、用途は別物です。
:::

## 8. クイックフィルターのモード一覧

フィルターをダッシュボード上で **対話的に操作** させるのが **クイックフィルター（フィルターの表示）** です。フィルターピル右クリック → 「フィルターを表示」で右サイドに UI が現れ、形式を変更できます。

| モード | 見た目 | 用途 |
|-------|-------|------|
| **単一値（リスト）** | ラジオボタン | 1 つだけ選ばせる |
| **単一値（ドロップダウン）** | プルダウン | 値が多いとき省スペース |
| **単一値（スライダー）** | スライダー | 順序付きの値で 1 つ選ぶ |
| **複数値（リスト）** | チェックボックス | 複数選択可 |
| **複数値（ドロップダウン）** | チェックボックス入りプルダウン | 複数選択 + 省スペース |
| **複数値（カスタムリスト）** | テキスト入力 | 値が極めて多いケース |
| **ワイルドカード一致** | テキスト入力 | 部分一致検索 |
| **範囲スライダー** | スライダー（連続値用） | `trip_total` の金額範囲など |
| **At Most / At Least** | スライダーの片側 | 上限 / 下限のみ |

::: tip 「すべての値（データソース）」と「関連する値」
クイックフィルターの **▼メニュー** からフィルターの母集合を切り替えられます。「関連する値」にすると **他のフィルターを反映した値のみ** が選択肢に出るため、対話 UI として親切になります。
:::

## やってみよう

`chicago_taxi_trips.hyper` で、フィルターと並べ替えを総合的に試します。

1. **基本ビューを準備**
   - 行に `company`、列に `SUM(trip_total)` の横棒グラフを作成
2. **ディメンションフィルター**
   - `payment_type` をフィルターシェルフへ → `Credit Card` のみチェック
3. **メジャーフィルター**
   - フィルターシェルフに `SUM(trip_total)` → 「少なくとも 10000」を指定
4. **上位 N フィルター**
   - `company` をフィルターシェルフへ → 「上位」タブ → `SUM(trip_total)` で上位 5
   - この時点で `payment_type = Credit Card` の中での上位 5 を見たい場合は、`payment_type` を **右クリック → 「コンテキストに追加」** で灰色に変える
5. **並べ替え**
   - 横棒の軸ヘッダーをクリックして降順に並べ替え
6. **ビンでヒストグラム**
   - `trip_miles` を右クリック → 「作成」 → 「ビン」 → サイズ `1`
   - 新しいシートを開き、列に `trip_miles (bin)`、行に `COUNT(trip_id)`
7. **グループの作成**
   - `payment_type` を右クリック → 「作成」 → 「グループ」
   - `Cash` と「Cash 系の値」を 1 つにまとめ、ビューで効果を確認
8. **クイックフィルターを表示**
   - フィルターシェルフの `payment_type` を右クリック → 「フィルターを表示」
   - 右側に出た UI の ▼ メニューから「複数値（リスト）」「単一値（ドロップダウン）」など切替

## まとめ

- 集計関数は `SUM` / `AVG` / `COUNT` / `COUNTD` / `MEDIAN` などから選び、メジャーピル右クリックで切り替えられます。
- フィルターは **抽出 → データソース → コンテキスト → ディメンション → メジャー → 表計算** の順に評価されます。
- メジャーフィルターは **集計後** に効くため、ビューの粒度を変えると挙動も変わります。
- **コンテキストフィルター** は上位 N の対象を絞るときの代表的な使いどころです。
- **グループは再ラベル、セットは IN/OUT 2 値化、ビンはメジャーの階級化** と、3 つの再分類道具は役割が明確に分かれます。
- **クイックフィルター** は単一値・複数値・範囲スライダー・ワイルドカードなど多彩なモードを持ち、ダッシュボードでの対話 UI を支えます。
