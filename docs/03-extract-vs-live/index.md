## 1. ライブ接続と抽出の違い

Tableau にデータをつなぐ方法は、大きく **ライブ接続 (Live)** と **抽出 (Extract)** の 2 つに分けられます。

| 項目 | ライブ接続 | 抽出 (.hyper) |
|------|----------|--------------|
| 実体 | クエリを毎回 **元の DB** に発行 | データを **Hyper エンジン** に取り込んだスナップショット |
| 鮮度 | 常に最新 | 抽出時点のコピー（更新が必要） |
| 速度 | DB / ネットワーク依存 | Hyper の高速カラムナで一般に速い |
| オフライン | DB に到達できないと使えない | `.hyper` だけで動作可能 |
| 課金影響 | クエリ毎にスキャン課金 (BQ など) | 抽出更新時のみ課金 |
| ファイル形式 | `.tds` / `.twb`（接続情報のみ） | `.hyper`（実データ）/ `.twbx` に同梱 |

データソースタブ右上に **「ライブ」** と **「抽出」** のラジオボタンがあり、ここで切り替えます。ライブから抽出に切り替えると、`.hyper` の保存ダイアログが表示されます。

:::

## 2. 抽出のメリット

抽出を使う動機は、単に「速いから」だけではありません。実務では次の 4 点が重なって採用理由になります。

### パフォーマンス（Hyper エンジン）

`.hyper` は Tableau 専用の **カラムナ型インメモリエンジン** です。集計クエリに最適化されており、ビュー操作のレスポンスが体感で大きく改善します。特に行数百万件規模のデータで効果が顕著です。

### ポータビリティ

`.twbx` に同梱すれば、データソースの認証情報を持たない相手にもワークブックを配布できます。出張先のオフラインノート PC でも動作する点が大きな利点です。

### オフライン可用性

VPN や DB の停止に左右されません。ダッシュボードのプレゼン中に DB が落ちて画面が真っ白、といった事故を防げます。

### データソース課金の削減

BigQuery のように **クエリのスキャン量で課金** されるサービスをライブで使うと、ビューを動かすたびに費用が発生します。抽出に切り替えれば、課金は更新ジョブ実行時のみに集約されます。

::: tip 「速さ」の理由
Hyper はカラム単位で圧縮・統計情報を持っており、`SUM(trip_total)` のような集計はインデックスをほぼフルで活用できます。同じデータでも CSV → Hyper にするだけで 10 倍以上速くなる場面は珍しくありません。
:::

## 3. ライブのメリット

抽出が万能というわけではありません。次のような場面ではライブを選びます。

| 場面 | 理由 |
|------|------|
| **リアルタイム性が必須** | 在庫・配車・センサー値など、分単位で更新されるデータ |
| **データが巨大すぎる** | Hyper に乗せきれない、あるいは抽出時間が長すぎる |
| **DB 側で複雑な処理が完結している** | マテリアライズドビューやストアド側で前処理済み |
| **セキュリティ要件で複製不可** | 個人情報・機密データを抽出ファイル化したくない |
| **行レベルセキュリティ (RLS) が DB 側** | DB 側のユーザー権限でフィルタしたい |

::: warning 「リアルタイム」のコスト
リアルタイム性はライブ接続の最大の強みですが、DB の負荷とコストを直接消費します。本当に分単位の鮮度が要るのか、抽出を 30 分おきに更新すれば足りるのか、設計時に見直しましょう。
:::

## 4. 抽出の作成

抽出は **データソースタブ → 抽出 → 編集** から設定します。主なオプションは次のとおりです。

### 抽出フィルター

抽出に **含める行を絞り込む** 機能です。たとえば 10 年分のデータのうち「2023 年のみ」を抽出する、`payment_type = 'Credit Card'` の行だけにする、といった用途です。

### 集計抽出

「ビューに表示されているディメンションのレベルで集計する」オプションです。たとえばすべてのビューが `company × 月` 単位までしか掘らないなら、抽出時点で集計しておくことで容量を劇的に削減できます。

### サンプリング（上位 N 行）

開発時に「とりあえず先頭 1000 行で動作確認したい」ときに使います。本番抽出前のリハーサル用と考えましょう。

## 5. 増分更新 / 完全更新

抽出は古くなるので、定期的に更新が必要です。更新には 2 つのモードがあります。

| モード | 動作 | 用途 |
|--------|------|------|
| **完全更新 (Full Refresh)** | 抽出全体を作り直す | ソースに過去データの修正が入る、ロジックを変えた、軽量データ |
| **増分更新 (Incremental Refresh)** | **指定列の最大値より大きい行だけ** を追加 | 追記型の巨大ログ、日次バッチ |

### 増分更新の設定

1. 抽出 → 編集 → 「増分更新で行を追加」にチェック
2. **増分の基準列** を選択（例: `trip_start_timestamp`）
3. 以降の更新時は、Tableau が「抽出内の `trip_start_timestamp` の最大値」を確認し、それより大きい行だけを取得

::: warning 増分更新の落とし穴
- ソース側で **過去日のデータが追記・修正** されても拾えません（例: 遅延データ）。定期的な完全更新を併用するのが安全です。
- 基準列に **重複** がある場合、最大値ちょうどの行は再取得されないことがあります。一意に増加する列を選ぶのが理想です。
:::

## 6. .hyper の管理

`.hyper` は実データを持つファイルなので、運用面の配慮が必要です。

### 配置

- **個人検証**: ローカルのドキュメントフォルダ
- **チーム共有**: Tableau Server / Cloud に **公開データソース** として登録し、`.hyper` の生成・配布を 1 箇所に集約
- **配布物**: `.twbx` に同梱するとシンプルだが、容量が膨らみがち

### 容量

`.hyper` はカラムナ圧縮が効くため、同じデータの CSV と比べて **数分の 1 〜 数十分の 1** になることが多いです。とはいえ 1 億行を超える規模では数 GB に達するため、抽出フィルター・集計抽出で削減を検討します。

### バージョン管理

`.hyper` はバイナリなので Git での差分管理には向きません。「ソースの定義 (`.tds` / `.tdsx`) は Git、データ (`.hyper`) は別の場所」と切り分けるのが一般的です。

## 7. BigQuery を抽出で使う場合の注意点

BigQuery は強力ですが、ライブ運用するとコスト・パフォーマンスの両面で課題が出やすいので、抽出と組み合わせることが多いサービスです。

### 課金の集中化

ライブだと **ビュー操作のたび** にスキャンが走り、課金も分散します。抽出にすれば、更新ジョブ実行時のスキャンに集約されるため、コスト把握と上限管理が容易になります。

### スケジュール更新

Tableau Server / Cloud 側で抽出の更新スケジュールを設定します。

- **更新頻度**: 業務要件に合わせて毎日 / 毎時 / 数時間おき
- **更新時間帯**: BQ 側の利用が少ない深夜帯にずらす
- **タイムゾーン**: スケジュールの時刻はサーバー側のタイムゾーンで動く点に注意

### パーティション・クラスタリングを活かす

抽出フィルターを **パーティション列** に揃えると、BQ 側のスキャン量も劇的に減ります。たとえば `trip_start_timestamp` で月別パーティションが切られているなら、抽出フィルターを月単位の範囲指定にすると効率的です。

::: tip カスタム SQL の使いどころ
BigQuery 側で複雑な前処理 (UNNEST、配列展開、複数ソースの統合) が必要なら、Tableau の接続時に **カスタム SQL** を書いて、その結果を抽出するパターンが有効です。ただし保守の観点から、可能なら BQ 側のビュー / マテリアライズドビューに移すのが望ましいです。
:::

## やってみよう

`.hyper` は既に抽出済みのファイルなので、本演習では「抽出をさらに加工 / 再生成する」ところを試します。BigQuery を持っている方は手順 6 まで含めてください。

1. **接続して抽出状態を確認**
   - `chicago_taxi_trips.hyper` に接続 → データソースタブを開く
   - 右上のラジオボタンを確認。`.hyper` 接続では既に「抽出」が選ばれているはずです
2. **抽出フィルターを追加**
   - 「抽出」横の「編集」 → 「フィルターを追加」 → `payment_type` → `Credit Card` のみにチェック
3. **集計抽出を試す**
   - 同じ編集ダイアログ内で「ビューに表示されているディメンションのデータを集計」を ON
   - サンプル抽出として `company × 月` の集計で再生成
4. **増分更新の設定（疑似）**
   - 「増分更新で行を追加」をチェック → 基準列に `trip_start_timestamp` を選択
   - 今回はファイル接続なので更新動作は限定的ですが、設定 UI を把握しておきましょう
5. **抽出の保存と容量比較**
   - 「すべて抽出」ボタンで `.hyper` を別名保存 → ファイルサイズを元ファイルと比較
6. **（任意）BigQuery で同等の流れを体験**
   - BigQuery `bigquery-public-data.chicago_taxi_trips.taxi_trips` にライブ接続 → 抽出に切り替え → スキャン量を BQ コンソールで確認

## まとめ

- **ライブ接続** は最新性に強く、**抽出 (.hyper)** はパフォーマンス・ポータビリティ・課金削減に強いという棲み分けです。
- 抽出には **抽出フィルター・集計抽出・サンプリング** といった削減オプションがあります。
- 更新方式は **完全更新** と **増分更新** があり、増分更新には基準列と「過去データの修正を拾えない」リスクが伴います。
- `.hyper` はカラムナ圧縮が効くため CSV より小さくなりますが、巨大データでは管理戦略が必要です。
- BigQuery のような **クエリ課金型** サービスは抽出 + スケジュール更新が定石で、抽出フィルターを **パーティション列** に揃えるとさらに効率的です。
