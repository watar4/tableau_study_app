## 1. 接続できるデータソースの種類

Tableau Desktop は非常に多くのデータソースに接続できます。スタート画面の「接続」ペインを開くと、大きく **3 グループ** に分かれて並んでいます。

| グループ | 例 | 特徴 |
|----------|----|------|
| **ファイルへ** | Excel、テキスト (CSV/TSV)、JSON、PDF、空間ファイル (Shapefile/GeoJSON)、統計ファイル、`.hyper` | ローカル / 共有フォルダ上のファイルを直接読む |
| **サーバーへ** | BigQuery、Snowflake、Amazon Redshift、Microsoft SQL Server、PostgreSQL、MySQL、Oracle | 認証情報を入力して DB に接続 |
| **保存済みデータソース** | Tableau Server / Cloud に公開済みのデータソース | 組織内で共有されたデータ定義を再利用 |

本ツールの演習では、軽量で再現性の高い **ファイル接続 (`.hyper`)** を中心に進めます。BigQuery などのサーバー接続は、認証情報や接続権限が必要なため、概念の理解にとどめ、実機演習は任意とします。

::: info ネイティブコネクタと ODBC
頻出 DB には専用のネイティブコネクタが提供され、最適化された SQL が発行されます。これに対し、汎用 ODBC / JDBC でつなぐことも可能ですが、パフォーマンスや関数互換性に差が出る場合があります。
:::

## 2. ファイル接続（Excel / CSV / .hyper）

ファイル接続はもっとも手軽な入口です。Excel・CSV・`.hyper` のいずれも、起動直後のスタート画面からドラッグ&ドロップ、あるいは「ファイルへ」セクションから選択するだけで接続できます。

| ファイル形式 | 用途 | 注意点 |
|------------|------|--------|
| **Excel (.xlsx / .xls)** | 業務でよく使われる集計表 | シートごとに別オブジェクトとして扱われる。結合セルや見出し行の混在に注意 |
| **テキスト (CSV / TSV)** | 軽量で互換性が高い | 文字コード (UTF-8 / Shift_JIS)、区切り文字、日付フォーマットを確認 |
| **`.hyper`** | Tableau の高速カラムナ形式 | 抽出ファイル本体。圧縮済みで読込が速く、本演習の基本データ形式 |

接続が完了すると **データソースタブ** が開きます。中央のキャンバスに使うシート（テーブル）をドラッグし、画面下の「データのプレビュー」で中身を確認しましょう。

![データソースタブと .hyper の接続例](/images/02-data-connection/datasource-tab.png)

::: tip .hyper を直接開く
`.hyper` は Tableau の抽出フォーマットそのものです。Excel/CSV と異なり、データ型・地理的役割・サムネイル情報が既に確定しているため、接続が非常に速く、本ツールの演習では `chicago_taxi_trips.hyper` を 1 クリックで開けば準備完了です。
:::

## 3. データベース接続（BigQuery を例に）

サーバー型 DB への接続は、ファイル接続と比べて **認証** と **課金** の考慮が増えます。ここでは Google BigQuery を例に概要だけ押さえます。

### 認証フロー

| 方式 | 概要 | 主な用途 |
|------|------|---------|
| **OAuth** | ブラウザで Google アカウントにログイン | 個人 PC からの探索利用 |
| **サービスアカウント (JSON 鍵)** | 鍵ファイルを Tableau に登録 | Tableau Server / Cloud のスケジュール更新 |

### 接続手順（概略）

1. 「サーバーへ」 → 「Google BigQuery」を選択
2. 認証方式を選び、ブラウザまたは鍵ファイルで認証
3. **請求プロジェクト** と **データセット** を選択
4. テーブルをキャンバスにドラッグ

::: warning BigQuery はクエリ課金
BigQuery はスキャンしたデータ量に応じて課金されます。ライブ接続で毎回フルスキャンが走ると意図せず高額になる場合があるため、本番運用では **抽出** に切り替えるか、`pickup_community_area` などでパーティション/クラスタを意識して絞り込みます。詳細は次章で扱います。
:::

本演習では BigQuery 接続は **概念理解のみ** とし、以降は同梱の `.hyper` を使います。

## 4. リレーションシップ vs 結合 vs ユニオン

複数テーブルを組み合わせる方法は **3 種類** あり、それぞれ目的とふるまいが異なります。

| 方式 | 何をするか | 結合タイミング | 粒度の扱い |
|------|-----------|---------------|----------|
| **リレーションシップ (Relationship)** | テーブル同士の関連を **論理的に定義** するだけ | ビューを作るたびに自動で最適な結合を生成 | ビューに使うフィールドに応じて Tableau が自動調整 |
| **結合 (Join)** | INNER / LEFT / RIGHT / FULL でテーブルを **物理的に 1 つに統合** | 接続時に固定的に発行 | 列が多対多になると行が膨張する |
| **ユニオン (Union)** | 同じスキーマの複数テーブルを **縦に積む** | 接続時に固定 | 行数が単純に加算される |

### 使い分けの目安

- **リレーションシップ**: 2019.3 以降のデフォルト。基本はこれを使えば困ることは少ない
- **結合**: 1 つのテーブルに「平らに」したい、あるいは複雑な結合条件 (`<`、`<>` など) が必要
- **ユニオン**: 月別 CSV を縦結合するなど、**同じ形のテーブル** を積む場面

::: tip リレーションシップが安全な理由
結合では LEFT JOIN によって NULL 行が生成されたり、多対多で `SUM` が二重計上されたりすることがあります。リレーションシップでは Tableau がビューの粒度に合わせて結合を組み立てるため、こうした集計ミスを避けやすくなります。
:::

## 5. 物理レイヤー / 論理レイヤー

リレーションシップを理解するには **2 階層のキャンバス** を区別する必要があります。

```
論理レイヤー (Logical Layer)
  └─ リレーションシップで結ばれた論理テーブル
        └─ 物理レイヤー (Physical Layer)
              └─ 結合・ユニオンで統合された物理テーブル
```

- **論理レイヤー**: データソースタブを開いて最初に表示される画面。各「箱」が **論理テーブル** で、線が **リレーションシップ**
- **物理レイヤー**: 論理テーブルをダブルクリックすると開く。中で **結合・ユニオン** を組み立てる場所

たとえば「乗車テーブル」と「会社マスタ」をリレーションシップで結びつつ、乗車テーブル内部では「2023 年 1 月〜12 月の月別 CSV をユニオン」している、といった組み合わせが可能です。

![論理レイヤー（外側）と物理レイヤー（内側）](/images/02-data-connection/logical-physical-layer.png)

## 6. データ型と地理的役割

接続直後にフィールドの **型** と **地理的役割** を整えると、後のビュー作りがスムーズになります。

### データ型の変更

データプレビューの各列ヘッダー左に小さなアイコンがあり、ここをクリックすると型を変更できます。

| アイコン | 型 |
|---------|----|
| `#` | 数値（整数 / 小数） |
| `Abc` | 文字列 |
| カレンダー | 日付 / 日時 |
| `T \| F` | ブール |
| 地球儀 | 地理的役割 |

Chicago Taxi では `pickup_community_area` は数値ですが「エリア識別子」なので、ディメンションに変換しておくのが定石です。

### 地理的役割の設定

`pickup_centroid_latitude` / `pickup_centroid_longitude` は数値として読み込まれますが、地図に使うには **地理的役割** の設定が必要です。

1. フィールドを右クリック → 「地理的役割」
2. 緯度なら **「緯度」**、経度なら **「経度」** を選択

これで地球儀アイコンに変わり、地図ビューで自動的に位置として扱われるようになります。

::: info WKT POINT 形式
`pickup_centroid_location` は `POINT(-87.6 41.9)` のような WKT (Well-Known Text) 形式の文字列です。Tableau は空間ファイル (Shapefile/GeoJSON) を直接読めますが、テキストの WKT を地理として使うには `MAKEPOINT` 関数などで明示的に変換するアプローチが一般的です。
:::

## 7. データインタープリター・ピボット・分割

Excel・CSV を読み込んだあとに役立つ **データ準備機能** が 3 つあります。すべてデータソースタブから利用します。

### データインタープリター

Excel の「装飾的なヘッダー」「結合セル」「タイトル行」「脚注」を **自動的にきれいな表に変換** する機能です。データソースタブ左下の「データインタープリターを使用」にチェックを入れると、Tableau が候補を提示します。

### ピボット

横長の表（例: `2023年1月`、`2023年2月`、... という列が並ぶ）を **縦長** に変換します。複数列を選択 → 右クリック → 「ピボット」。横持ち → 縦持ちにすることで、Tableau の「月」軸として時系列分析が可能になります。

### 分割

1 つの文字列フィールドを区切り文字で複数フィールドに分割します。たとえば `company` に「Taxi Affiliation Services - 5074」のようなハイフン区切りの会社名 + 番号が入っているとき、「分割」または「カスタム分割」で会社名と番号を別フィールドにできます。

![データインタープリター・ピボット・分割の操作画面](/images/02-data-connection/data-prep-tools.png)

::: tip 接続段階で整えるか、計算フィールドで整えるか
データ準備機能は **接続段階で物理的に変形** します。一方、計算フィールドは **論理的に派生フィールドを足す** だけで元データは変えません。汎用的に再利用するなら計算フィールド、データ自体が歪なら接続段階で整えるのが目安です。
:::

## やってみよう

同梱の `chicago_taxi_trips.hyper` で、データ接続周りの操作を体験しましょう。

1. **`.hyper` に接続**
   - Tableau Desktop を起動 → 「ファイルへ」 → 「その他のファイル」 → `chicago_taxi_trips.hyper` を選択
   - データソースタブが開き、約 100 万行が認識されます
2. **データプレビューを確認**
   - 画面下のプレビューを横スクロールし、`trip_id`、`company`、`payment_type`、`trip_total` などの列を確認
3. **数値 ID をディメンションに変換**
   - `pickup_community_area` を右クリック → 「ディメンションに変換」
   - 同様に `dropoff_community_area` も変換
4. **地理的役割を設定**
   - `pickup_centroid_latitude` を右クリック → 「地理的役割」 → 「緯度」
   - `pickup_centroid_longitude` を右クリック → 「地理的役割」 → 「経度」
5. **フィールド名をリネーム**
   - `trip_total` をダブルクリック → 「合計料金 (USD)」のように日本語名に変更（業務での共有時に効果的）
6. **シートに移動して動作確認**
   - 左下の `Sheet 1` をクリック
   - `company` を行、`SUM(trip_total)` を列にドラッグして会社別売上の棒グラフを作成
7. **（任意）BigQuery への接続を試す**
   - 「サーバーへ」 → 「Google BigQuery」 → OAuth 認証 → 公開データセット `bigquery-public-data.chicago_taxi_trips` のテーブルをプレビュー（課金注意、本演習では実行任意）

## まとめ

- Tableau は **ファイル / サーバー / 保存済みデータソース** の 3 系統に接続でき、本ツールでは `.hyper` を中心に使います。
- 複数テーブルを組み合わせる方法は **リレーションシップ / 結合 / ユニオン** の 3 種類で、デフォルトかつ安全なのはリレーションシップです。
- データソースには **論理レイヤー** と **物理レイヤー** の 2 階層があり、論理テーブルの中で結合やユニオンを組み立てます。
- 緯度経度のような数値フィールドは **地理的役割** を設定することで地図に使えるようになります。
- **データインタープリター・ピボット・分割** を使えば、接続段階で歪なデータを整形できます。
