## 1. LOD とは（集計粒度を明示する）

**LOD (Level of Detail) 表現** は、計算式の中で「**どの粒度で集計するか**」を明示できる構文です。通常、Tableau の集計はビュー上のディメンションで暗黙に決まりますが、LOD を使えば「ビューと違う粒度」で集計させられます。

### 基本構文

```
{ <スコープキーワード> <ディメンション> : <集計式> }
```

スコープキーワードには 3 種類あります。

| キーワード | 粒度の決め方 |
|------------|----------------|
| **FIXED** | ビューと無関係に、指定したディメンションだけで集計 |
| **INCLUDE** | ビューの粒度 **+** 指定ディメンションを **追加** して、より細かい粒度で集計 |
| **EXCLUDE** | ビューの粒度 **から** 指定ディメンションを **除外** して、より粗い粒度で集計 |

### 簡単な例

「データセット全体の平均料金」をスカラー値として欲しい場合は、ディメンション無しの FIXED を使います。

```
{ FIXED : AVG([trip_total]) }
```

「会社ごとの最古乗車日」を、ビューに会社を置かなくても取得したい場合はこう書きます。

```
{ FIXED [company] : MIN([trip_start_timestamp]) }
```

::: tip LOD は「集計を 1 度だけ事前に作って使い回す」イメージ
通常の集計は「ビューが見ている粒度で都度集計」しますが、LOD は「**この粒度の集計値を 1 つの列として確保**」してくれる仕組みです。これにより行レベル計算の中でも使えるようになります。
:::

## 2. FIXED の構文と挙動

**FIXED** は最も使われる LOD で、「ビューに何が置かれていようと、指定した粒度で固定して集計する」関数です。

### 構文

```
{ FIXED [Dim1], [Dim2], ... : <集計式> }
```

ディメンションを省略するとデータセット全体のスカラー値になります。

```
{ FIXED : SUM([trip_total]) }       … データ全体の合計
{ FIXED [company] : COUNT([trip_id]) }   … 会社別の取引件数
```

### 重要な性質: 行レベルで使える

FIXED の戻り値は **「ビューと独立に決まった集計値」** のため、**行レベル計算と混在させられます**。10 章で学んだ「混在エラー」を回避する代表的な手法です。

```
[trip_total] - { FIXED : AVG([trip_total]) }
```

これは「全体平均との差」を行レベルで計算しています。LOD の戻り値はスカラー（または行に紐づく値）として扱えるため、エラーになりません。

### 重複削除や生涯購買回数

`taxi_id` ごとの「総乗車回数」をビューに置けば、車両ごとの稼働度合いがすぐ見えます。

```
{ FIXED [taxi_id] : COUNT([trip_id]) }
```

これをディメンションに変換してビン化すれば、「稼働の少ない車両群」「ヘビーユーザー的な車両」など分布も描けます。

| 用途 | 式の例 |
|------|--------|
| 全体スカラー | `{ FIXED : SUM([trip_total]) }` |
| キー単位の合計 | `{ FIXED [taxi_id] : COUNT([trip_id]) }` |
| キー単位の最古日付 | `{ FIXED [taxi_id] : MIN([trip_start_timestamp]) }` |
| 結合キー単位の最大値 | `{ FIXED [company], [pickup_community_area] : MAX([trip_total]) }` |

## 3. INCLUDE の構文と挙動

**INCLUDE** は「ビューに **含まれていない** ディメンションを集計時に **追加** して、より細かい粒度で計算する」 LOD です。

### 構文

```
{ INCLUDE [追加するDim] : <集計式> }
```

### 何が嬉しいか

たとえばビューが「会社別の `trip_total` 合計」を表示している状態で、「**車両 1 台あたりの平均**」を見たいケースを考えます。普通に書いた `AVG([trip_total])` は「行レベルの平均」になってしまい意図に合いません。

```
{ INCLUDE [taxi_id] : SUM([trip_total]) }
```

このように `taxi_id` を INCLUDE すると、内部的に「会社 × 車両ごとの合計」を求め、ビュー側の「会社」粒度で集計関数（AVG など）を適用すれば、「**会社別の、車両 1 台あたり平均売上**」が得られます。

```
AVG({ INCLUDE [taxi_id] : SUM([trip_total]) })
```

::: info INCLUDE は周囲を集計でくるむのが定石
INCLUDE 単体ではビューより細かい粒度の値が並んでしまうため、`AVG()` や `SUM()` などで再集計するのが一般的なパターンです。
:::

| 場面 | 式の形 |
|------|--------|
| 顧客 1 人あたり平均 | `AVG({ INCLUDE [Customer] : SUM([Sales]) })` |
| 車両 1 台あたり平均稼働時間 | `AVG({ INCLUDE [taxi_id] : SUM([trip_seconds]) })` |
| 注文 1 件あたり最大値 | `MAX({ INCLUDE [Order ID] : SUM([Sales]) })` |

## 4. EXCLUDE の構文と挙動

**EXCLUDE** は「ビューに **ある** ディメンションを **除外** した粒度で集計する」 LOD です。

### 構文

```
{ EXCLUDE [除外するDim] : <集計式> }
```

### 典型例: 構成比

ビューが「年 × 月」で売上を表示しているとき、「**月別売上 / 年の合計**」という構成比を作りたいとします。

```
SUM([trip_total]) / SUM({ EXCLUDE [Month] : SUM([trip_total]) })
```

EXCLUDE で「月」を除けば年粒度の合計が得られ、それを分母にすれば「年内の月構成比」になります。

### FIXED との違い

EXCLUDE は **ビューに依存して粒度が決まる** 点が FIXED と決定的に違います。同じ「年合計」を出すにも、

| キーワード | 挙動 |
|------------|------|
| `{ FIXED [Year] : SUM([trip_total]) }` | ビューに何があっても、年で固定 |
| `{ EXCLUDE [Month] : SUM([trip_total]) }` | ビューにあるディメンションから「月」を取り除いて集計（ビューに年があれば年単位） |

ビューの構造を変えたとき、EXCLUDE は連動して結果が変わり、FIXED は変わりません。

::: warning EXCLUDE は単独で使うと粒度が落ちる
EXCLUDE は「ビュー粒度より粗い」値を返すので、ビューに置くと同じ値が複数行に複製されます。比率計算など、**他の式と組み合わせて使う**のが基本です。
:::

## 5. LOD と各フィルターの評価順序

LOD を使いこなすうえで最も重要な知識が **フィルターの評価順序** です。Tableau は以下の順序でフィルターと計算を評価します。

```
1. データソース抽出フィルター（.hyper 作成時）
2. データソースフィルター
3. コンテキストフィルター
4. FIXED LOD
5. ディメンションフィルター
6. INCLUDE / EXCLUDE LOD
7. メジャーフィルター
8. 表計算（およびそれをベースにしたフィルター）
```

### 何が問題になるか

- **FIXED はディメンションフィルターより先に評価される** ため、フィルターを掛けてもビューに反映されません。たとえば `pickup_community_area = 8` のフィルターを掛けても、`{ FIXED : SUM([trip_total]) }` は **データ全体の合計** を返し続けます。
- **INCLUDE / EXCLUDE はディメンションフィルター後に評価** されるので、フィルターは結果に効きます。

### 解決策: コンテキストフィルターに昇格

FIXED にもディメンションフィルターを効かせたい場合は、フィルターを **コンテキストフィルター** に昇格させます。手順はフィルター棚のアイテムを右クリック →「コンテキストに追加」を選びます。コンテキストフィルターは FIXED の前に評価されるため、想定どおりに絞り込んだ集計が得られます。

| やりたいこと | 設定 |
|--------------|------|
| FIXED に絞り込みを反映 | フィルターをコンテキストに昇格 |
| FIXED を絞り込みに依存させたくない | 通常のディメンションフィルターのまま |
| 表計算の結果を絞り込みたい | 表計算フィルターを使う（メジャーフィルター以降） |

::: tip コンテキストフィルターは性能トレードオフ
コンテキストフィルターは一時テーブルを作るような処理のため、適用範囲が大きすぎると遅くなる場合があります。**「FIXED に効かせる必要があるフィルターだけ」をコンテキストに昇格** するのが現実的です。
:::

## 6. ユースケース 1: 顧客別初回購入日

LOD のもっとも有名なユースケースが「**顧客（タクシー）ごとの初回乗車日**」です。Chicago Taxi では `taxi_id` を顧客とみなして考えます。

```
{ FIXED [taxi_id] : MIN([trip_start_timestamp]) }
```

この計算フィールドを `初回乗車日` と命名し、計算式中で参照できます。たとえば「初回乗車から何日目の乗車か」は次のとおりです。

```
DATEDIFF('day', { FIXED [taxi_id] : MIN([trip_start_timestamp]) }, [trip_start_timestamp])
```

これにより、各乗車レコードに「車両のデビューから何日目の乗車か」が付与されます。0 日目が初日です。

::: info FIXED LOD の戻り値はディメンションに変換できる
計算フィールドを右クリック → 「ディメンションに変換」 すれば、軸として使えます。たとえば `初回乗車日` を年単位（YEAR）に丸めれば「**初回乗車年**」というコホート分類になります。
:::

## 7. ユースケース 2: 構成比（全体・カテゴリ別）

### 全体構成比

ビューに `company` を置いた状態で、「全体に対する各社のシェア」を出します。

```
SUM([trip_total]) / { FIXED : SUM([trip_total]) }
```

書式設定でパーセント表示にすれば、各社シェアが取得できます。WINDOW_SUM での実装と異なり、**ビューにディメンションを追加しても分母が変わらない** のが LOD 流の特徴です。

### カテゴリ別構成比（地域別シェア）

ビューに `pickup_community_area` と `company` を置いて「**地域ごとの会社シェア**」を出すなら、分母は「地域単位」にします。

```
SUM([trip_total]) / { FIXED [pickup_community_area] : SUM([trip_total]) }
```

| 構成比の種類 | 分母の式 |
|--------------|----------|
| 全体に対するシェア | `{ FIXED : SUM([trip_total]) }` |
| 地域内シェア | `{ FIXED [pickup_community_area] : SUM([trip_total]) }` |
| 会社 × 年内シェア | `{ FIXED [company], YEAR([trip_start_timestamp]) : SUM([trip_total]) }` |

::: tip 表計算との使い分け
WINDOW_SUM ベースの構成比は **ビューの方向に強く依存**、LOD ベースの構成比は **粒度を明示的に固定** という違いです。ダッシュボードでフィルターを掛けても分母を変えたくない場合は LOD、ビュー上の現在表示を分母にしたい場合は表計算を選びます。
:::

## 8. ユースケース 3: コホート分析の土台

コホート分析は「同期入社・同期登録の集団を時間軸で追う」分析です。LOD があれば自然に書けます。

### 手順 1: 初回乗車年（コホート）

```
YEAR({ FIXED [taxi_id] : MIN([trip_start_timestamp]) })
```

### 手順 2: 経過月数

```
DATEDIFF('month',
  { FIXED [taxi_id] : MIN([trip_start_timestamp]) },
  [trip_start_timestamp]
)
```

### 手順 3: コホート粒度の指標

「コホート × 経過月数」のクロス集計表に `COUNTD([taxi_id])` を置けば、**残存車両数の推移**（リテンションカーブの土台）が見えます。経過月 0 の値で割れば残存率になります。

```
COUNTD([taxi_id]) /
  WINDOW_MAX(COUNTD([taxi_id]))
```

## 9. パフォーマンスと留意点

LOD は強力ですが、安易に多用すると重くなります。設計上の注意点を押さえます。

### パフォーマンスのポイント

- **抽出データソース** (`.hyper`) は LOD に最適化されており、ライブ接続より高速になりやすい。
- **FIXED のキーが多いほど** 内部的なグルーピングが増え、コストが上がる。
- **INCLUDE/EXCLUDE はビュー再描画ごとに評価** されるため、ダッシュボードのレイアウトが複雑だと累積コストが大きい。
- **ネストはできない**。`{ FIXED ... : { FIXED ... : ... } }` のような書き方はエラーになる。回避策は内側を別の計算フィールドにすること。

### LOD ネストの回避方法

```
// 計算フィールド A
{ FIXED [taxi_id] : SUM([trip_total]) }

// 計算フィールド B（A を参照）
{ FIXED [company] : AVG([A]) }
```

これで「車両ごとに合計してから、会社ごとに平均」という二段の集計が書けます。

### よくある落とし穴

| 症状 | 原因 | 対策 |
|------|------|------|
| フィルターを掛けても FIXED の値が変わらない | FIXED はディメンションフィルター前に評価 | コンテキストフィルターに昇格 |
| INCLUDE の結果が大きすぎる | 集計関数で囲んでいない | `AVG()` などでくるむ |
| EXCLUDE で同じ値が並ぶ | 粒度がビューより粗い仕様 | 比率・差分で使う |
| 「集計と非集計の混在」エラー | LOD を集計内で使わずそのまま並べた | LOD を `SUM()` 等で囲むか、文脈を統一 |

## 10. LOD と表計算の使い分け復習

ここまでの内容を、表計算 (11 章) と並べて再整理します。

| 観点 | LOD | 表計算 |
|------|-----|--------|
| 評価タイミング | データソースクエリ内 | ビュー描画後 |
| ビューへの依存 | 弱い（粒度を明示） | 強い（並び・構造に依存） |
| 行レベル計算との混在 | 可能（FIXED の戻り値は行レベルで使える） | 不可 |
| 順序の利用 | できない | できる（累計、前後、順位） |
| パフォーマンス | データソース負荷あり | クライアント側で軽量 |
| 典型用途 | 顧客別初回購入、固定スカラー、コホート | 累計、前年比、移動平均、順位 |

### 決め方の指針

- 「**ビューの並びや位置**」を使うなら → 表計算
- 「**ビューと独立した粒度の値**」が欲しいなら → LOD
- 「**行レベル計算の中で集計値を使いたい**」なら → FIXED LOD
- 「**ダッシュボードフィルターで分母を変えたくない**」なら → FIXED + 必要ならコンテキスト

## やってみよう

Chicago Taxi で LOD の典型を体験します。

1. **データ全体平均との差**: 計算フィールド `中央値乖離 = [trip_total] - { FIXED : AVG([trip_total]) }` を作成。`company` を行に置いてビン分布を確認。
2. **車両別の総乗車回数**: `車両別乗車数 = { FIXED [taxi_id] : COUNT([trip_id]) }` を作成。ヒストグラムにして「ヘビー車両」と「ライト車両」の分布を見ます。
3. **初回乗車日のコホート**: `初回乗車年 = YEAR({ FIXED [taxi_id] : MIN([trip_start_timestamp]) })` を作成し、ディメンションに変換。
4. **経過月数**: `経過月 = DATEDIFF('month', { FIXED [taxi_id] : MIN([trip_start_timestamp]) }, [trip_start_timestamp])` を計算フィールドに。
5. **コホートビュー**: `初回乗車年` を行、`経過月` を列、`COUNTD(taxi_id)` をテキストに置きヒートマップ化。
6. **シェアの計算**: `会社シェア = SUM([trip_total]) / { FIXED : SUM([trip_total]) }` をビューに追加。
7. **フィルターの順序を実験**: `pickup_community_area = 8` のディメンションフィルターを掛け、`{ FIXED : SUM([trip_total]) }` の値が変わらないことを確認。次に右クリック →「コンテキストに追加」で挙動が変わることを観察。
8. **INCLUDE で平均を変える**: `車両平均 = AVG({ INCLUDE [taxi_id] : SUM([trip_total]) })` を `company` ビューに置き、`AVG([trip_total])` との差を観察します。

## まとめ

- LOD は `{ FIXED/INCLUDE/EXCLUDE [Dim] : 集計式 }` の構文で、計算式の中に **粒度を明示** できる仕組み。
- **FIXED** はビューに依存せず指定粒度で固定し、**行レベル計算とも混在可能**。スカラー定数化やキー単位集計に最適。
- **INCLUDE** はビュー粒度より細かく、**EXCLUDE** は粗くする。両者ともビュー構造に連動。
- フィルター評価順序は **抽出 → DS → コンテキスト → FIXED → ディメンション → INCLUDE/EXCLUDE → メジャー → 表計算**。FIXED に絞り込みを効かせたいときは **コンテキストフィルター** を使う。
- 顧客別初回購入日、構成比、コホート分析が LOD の三大ユースケース。
- LOD は **ネスト不可**。多段の集計は中間計算フィールドを経由する。
- 表計算 vs LOD は「**順序を使うか / 粒度を固定するか**」で判断する。
