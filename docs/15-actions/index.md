## 1. アクションの種類一覧

**アクション**は、ユーザーの操作（クリック・ホバー・メニュー選択）に応じてダッシュボードを動的に変化させる仕組みです。アクションがあるかどうかで、ダッシュボードの「読み物」と「探索ツール」が分かれると言ってよいくらい重要な機能です。

ダッシュボード（またはワークシート）のメニューから「**ダッシュボード**」 → 「**アクション**」 → 「**アクションの追加**」で設定します。

| 種類 | 内容 | 主な用途 |
|------|------|----------|
| **フィルター** | 選んだマークの値で、他のシートをフィルターする | クリックで他シートを絞り込む |
| **ハイライト** | 選んだマークと同じ値を持つマークを強調表示 | クロス絞り込みせず、目立たせるだけ |
| **URL** | 外部 URL を開く | 関連ドキュメント・別システムへ遷移 |
| **パラメーターの変更** | クリックでパラメーター値を書き換え（13 章参照） | 指標切替・しきい値変更 |
| **セット値の変更** | クリックでセットのメンバーを書き換え | 動的ドリルダウン |
| **シートに移動** | 別のダッシュボード/シートに遷移 | ナビゲーション |

![アクション追加ダイアログ（種類選択）](/images/15-actions/action-types.png)

::: tip 共通の構成要素
どのアクションも「**ソース（操作を受け付けるシート）**」「**ターゲット（変化が起きる先）**」「**トリガー（ホバー/選択/メニュー）**」「**選択解除時の挙動**」を指定するという共通構造を持ちます。最初は混乱しますが、この型を覚えると一気に楽になります。
:::

## 2. フィルターアクション

最も使用頻度が高いのが**フィルターアクション**です。ソースシートで選んだマークの値を使って、ターゲットシートを絞り込みます。

### 設定ダイアログの主な項目

| 項目 | 内容 |
|------|------|
| **名前** | アクションの識別名 |
| **ソースシート** | クリックを受け付けるシート |
| **アクションの実行対象** | ホバー / 選択（クリック） / メニュー |
| **ターゲットシート** | フィルターを掛ける先のシート |
| **選択をクリアした結果** | フィルター結果を保持 / すべて表示 / すべて除外 |
| **対象フィルター** | すべてのフィールド / 選択したフィールド |

### 「選択をクリアした結果」の挙動

- **フィルター結果を保持**: 直前の選択結果がそのまま残る
- **すべての値を表示**: フィルターが解除されて全件表示に戻る（多くの場合これが直感的）
- **すべての値を除外**: 何もマークを選んでいない初期状態で「空表示」になる。KPI を「クリックされたら表示」にしたいときに使う

### 対象フィルター（フィールドの絞り込み）

「すべてのフィールド」だとソースとターゲットの共通フィールドすべてが連動します。「選択したフィールド」を選ぶと、たとえば `company` だけ連動させて `payment_type` は無視、といった制御が可能です。

![フィルターアクションの設定ダイアログ](/images/15-actions/filter-action.png)

::: info シート上の「フィルターとして使用」ボタン
ダッシュボード上でシートのタイトルバー右にあるじょうご型のアイコン（「フィルターとして使用」）をクリックすると、そのシートをソースとするフィルターアクションが自動生成されます。手っ取り早く対話性を持たせたいときに便利です。
:::

## 3. ハイライトアクション

**ハイライトアクション**は、ターゲットシート全体をフィルターするのではなく、「選んだ値と一致するマークだけを強調表示する」アクションです。

| 観点 | フィルター | ハイライト |
|------|-----------|-----------|
| 他シートの表示 | 絞り込まれて消える | 全件残る（一致するものだけ強調） |
| 全体感の把握 | 失われる | 維持される |
| 用途 | 詳細ドリルダウン | 系列の追跡・比較 |

たとえば「会社別の月次トレンド（複数線）」上で、棒グラフから 1 社を選ぶと、その会社の線だけ濃く・他は灰色に薄くする、という見せ方ができます。

### 設定ダイアログ

- ソースシート、ターゲットシート、トリガー（ホバー/選択/メニュー）
- **対象フィールド**: 「選択したフィールド」を指定すれば、どのフィールドの値で一致を取るかを明示できる

::: tip 凡例ハイライターと違うのか
ビュー右側にある色凡例の右上「ハイライターボタン」もハイライト機能ですが、こちらは「凡例の値をクリックして強調」する仕組みです。ハイライトアクションは「シート間のクリック連動」で、用途が異なります。
:::

## 4. URL アクション

**URL アクション**は、ユーザー操作に応じて外部 URL を開きます。社内ポータル、別のダッシュボード、Google マップ、社内 Wiki などへの導線として使います。

### 動的に URL を組み立てる

URL の中にフィールドやパラメーターの値を埋め込めます。プレースホルダは `<` `>` で囲みます。

```
https://www.google.com/search?q=<company>
```

`company` フィールドの値がクリック時に置換され、たとえば「Flash Cab」を選んだら `?q=Flash%20Cab` の検索結果が開きます。

| プレースホルダ | 内容 |
|----------------|------|
| `<フィールド名>` | クリックされたマークのフィールド値 |
| `<パラメーター名>` | パラメーターの現在値 |
| `<URL Encoded フィールド名>` | URL エンコード済みの値（明示指定） |

### トリガーとブラウザ挙動

- 「メニュー」: マーク右クリック → ツールヒントのリンクから開く（誤クリック防止に向く）
- 「選択」: クリックで即時開く（押した瞬間にブラウザが立ち上がる点に注意）
- 「ホバー」: ホバーで開く（基本的に推奨しない。意図せず開いてしまう）

![URL アクションでフィールド値を埋め込む設定](/images/15-actions/url-action.png)

::: warning 機微情報を URL に乗せない
URL は履歴・ログに残ります。個人情報や認証トークンを含む URL を作らないように注意しましょう。
:::

## 5. パラメーターアクション（再掲）

13 章で扱った**パラメーターアクション**もアクションの一種です。ダッシュボードのアクションメニューから「**パラメーターの変更**」を選択して設定します。

主な使いどころ:

- 棒グラフで会社を選ぶと、別シートの計算で参照される会社名パラメーターが切り替わる
- マップ上のエリアを選ぶと、ダッシュボードタイトルにそのエリア名が反映される
- スライダーをドラッグするのではなくマークのクリックで値を変える、というインターフェース

セットアクションと違って、パラメーターは単一値であることに注意してください。複数選択結果を反映したい場合はセットアクションを使います。

## 6. シートに移動（ナビゲーション）

**シートに移動**アクション（ナビゲーションアクション）は、別のダッシュボード・ワークシート・ストーリーへ遷移します。

設定方法は 2 通りあります。

1. アクションダイアログから「**シートに移動**」を追加。ソースシートのクリック等をトリガーにする。
2. ダッシュボードに「**ナビゲーション**」オブジェクト（ボタン）を配置し、遷移先と表示テキスト/画像を設定する。

### 想定シナリオ

- 概要ダッシュボードから明細ダッシュボードへ「もっと見る」ボタンで遷移
- カテゴリ別シートを切り替えるタブ風 UI（各タブはナビゲーションボタン）
- 「戻る」ボタンで概要ダッシュボードへ復帰

::: info Tableau Public でも動く
シートに移動アクションは Tableau Public 上でも動作します。1 つのワークブックの中で複数ダッシュボードを遷移するアプリ風 UI を構築できます。
:::

## 7. アクションをチェーンする際の注意

複数のアクションを 1 つのダッシュボードに設定し始めると、思わぬ挙動に出会うことがあります。以下に典型的な落とし穴を挙げます。

### よくあるトラブル

| 症状 | 原因 | 対処 |
|------|------|------|
| クリックしてもターゲットが変わらない | ソース/ターゲットのシート指定間違い、共通フィールドがない | ダイアログを再確認。「対象フィールド」を「選択したフィールド」で明示 |
| 元に戻せない | 「選択をクリアした結果」が「すべて除外」になっている | 「すべての値を表示」に変更 |
| フィルターが効きすぎる | 「すべてのフィールド」連動で、意図しないフィールドまで一致条件に | 「選択したフィールド」で限定 |
| 複数アクションが同時発火 | 同じソース・トリガーで複数のアクションを設定 | アクション一覧で順序と発火条件を確認 |
| URL が文字化け | URL エンコード未指定 | プレースホルダで「URL エンコード」を明示 |

### 設計のコツ

- アクションは**ダッシュボード単位**で持たせる（ワークシート単位より管理しやすい）
- 命名規約を決めておく（例: `フィルタ_棒→トレンド`）。一覧で何のアクションか分かりやすくなる
- 触る人が誤操作しても「**選択解除で初期状態に戻る**」設計にしておくと、リカバリが楽

::: warning アクション数の上限
アクション自体に明確な上限はありませんが、数が増えるとパフォーマンスが落ち、挙動の把握も難しくなります。1 つのダッシュボードでアクションが 10 個を超えると複雑度のサインです。
:::

## やってみよう

Chicago Taxi の 3 シートダッシュボードに対話性を加えます。

1. **ベースのダッシュボードを開く**
   - 14 章で作成した「会社別 + 月次 + 支払方法別」のダッシュボードを用意。
2. **フィルターアクションを設定**
   - メニュー「ダッシュボード」 → 「アクション」 → 「アクションの追加」 → 「フィルター」
   - ソース: 会社別シート、ターゲット: 月次トレンドシート、トリガー: 選択
   - 選択をクリアした結果: 「すべての値を表示」
3. **ハイライトアクションを設定**
   - 別のアクションとして追加。ソース: 支払方法別シート、ターゲット: 月次トレンドシート、対象フィールド: `payment_type`。
4. **動作確認**
   - 会社別シートで「Flash Cab」をクリック → トレンドが Flash Cab のみに絞り込まれる。
   - 支払方法別シートで「Cash」をクリック → トレンドの線で Cash の色だけ強調される。
5. **URL アクションを追加**
   - ソース: 会社別シート、URL: `https://www.google.com/search?q=<company>+taxi+chicago`、トリガー: メニュー。
   - 会社マーク右クリック → ツールヒントのリンクから検索ページが開くことを確認。
6. **ナビゲーションボタンの追加**
   - ダッシュボードを 2 枚目作成（「明細ダッシュボード」）。
   - 元のダッシュボードに「ナビゲーション」オブジェクトを配置し、遷移先に明細ダッシュボードを指定。
7. **タブ風 UI（任意）**
   - 概要・明細の 2 つのダッシュボードそれぞれにナビゲーションを 2 つずつ置き、互いに行き来できるようにする。
8. **アクション整理**
   - 「アクション」ダイアログで設定したアクション一覧を確認し、命名を整理。

---

## まとめ

- アクションは「ソース / ターゲット / トリガー / 選択解除時の挙動」という共通構造を持ちます。
- **フィルター**は他シートを絞り込み、**ハイライト**は強調するだけで全体感を保ちます。
- **URL アクション**は `<フィールド名>` で動的に URL を組み立てられ、外部リソースへの導線になります。
- **シートに移動**アクションとナビゲーションオブジェクトで、ダッシュボード間の遷移 UI を作れます。
- アクションが増えるほど挙動が複雑になるため、命名規約と「選択解除で初期状態に戻る」設計を心がけましょう。
