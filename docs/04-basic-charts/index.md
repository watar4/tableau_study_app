## 1. チャート選定の考え方

「どのチャートを使うか」は見栄えではなく **可視化の目的** から逆算します。代表的な 6 つの目的軸を押さえると、迷う場面が大幅に減ります。

| 目的 | 主なチャート | Chicago Taxi での例 |
|------|------------|-------------------|
| **比較** | 棒グラフ・ハイライトテーブル | 会社別の `SUM(trip_total)` を並べる |
| **推移** | 折れ線・面グラフ | 月別 `SUM(trip_total)` の推移 |
| **分布** | ヒストグラム・ボックスプロット | `trip_miles` の分布 |
| **構成** | 積み上げ棒・ツリーマップ・円 | `payment_type` の構成比 |
| **関係** | 散布図・バブルチャート | `trip_miles` と `trip_total` の関係 |
| **地理** | 記号マップ・塗り分けマップ | 乗車地 (`pickup_centroid_*`) の分布 |

::: tip まず「比較・推移・分布」から
6 つすべてを使いこなす必要はなく、業務ダッシュボードの 7〜8 割は **比較・推移・分布** で構成できます。これらを確実に作れるようになってから、関係・構成・地理へ広げるのが効率的です。
:::

## 2. 棒グラフ（縦/横/積み上げ/100% 積み上げ）

棒グラフは **比較** の王道で、最初に習得すべきチャートです。

| 種類 | 用途 | 作り方の要点 |
|------|------|-----------|
| **縦棒** | 数件のカテゴリ比較 | 列=ディメンション、行=メジャー |
| **横棒** | カテゴリが多い・ラベルが長い | 行=ディメンション、列=メジャー（並べ替えしやすい） |
| **積み上げ棒** | 全体と構成を同時に見る | マークカードの「色」に内訳ディメンション |
| **100% 積み上げ棒** | 構成比だけを比較 | クイック表計算「合計に対する割合」を「テーブル (横)」で適用 |

### Chicago Taxi での例

- 列に `company`、行に `SUM(trip_total)` → 会社別売上の縦棒
- 行に `company`、列に `SUM(trip_total)` → 横棒（会社が多いので推奨）
- 色に `payment_type` をドラッグ → 支払方法ごとに積み上げ
- `SUM(trip_total)` を右クリック → 「クイック表計算」 → 「合計に対する割合」 → 100% 積み上げに

## 3. 折れ線グラフ

折れ線は **時系列の推移** を見るための定番です。

- 列に **連続の日付** (`MONTH(trip_start_timestamp)` を緑のピル）
- 行に `SUM(trip_total)`
- マークタイプは自動で「線」になります

### 日付の粒度（年 / 四半期 / 月 / 日）

日付フィールドを列にドラッグすると、デフォルトでは **不連続の YEAR** が入ります。右クリック → 「連続」 → 「月」のように切り替えることで、滑らかな時系列軸になります。

| 粒度 | 用途 |
|------|------|
| **年** | 長期トレンド |
| **四半期 / 月** | 業務レポートの基本単位 |
| **週 / 日** | 短期の動き、曜日特性 |
| **時間** | タクシー需要のピーク時間帯分析 |

::: tip 月の途中までしかデータがない場合
たとえば最新月のデータが「20 日まで」のように途切れていると、月単位の折れ線で **最終点が極端に低くなる** ことがあります。フィルターで「完全な月のみ」に絞るか、表記で注意書きを入れる工夫が必要です。
:::

## 4. 散布図・バブルチャート

散布図は **2 変数の関係** を見るチャートです。

- 列に `SUM(trip_miles)`、行に `SUM(trip_total)` を置き、マークを「円」に
- このままでは 1 点しか描かれないため、**詳細** シェルフに `trip_id`（または `taxi_id`）を入れて粒度を確保
- アナリティクスペインの「トレンドライン」をドラッグすれば回帰直線も追加可能

### バブルチャート

サイズを変数に紐づけた散布図が **バブルチャート** です。たとえば「色 = `payment_type`、サイズ = `COUNTD(taxi_id)`、X = `AVG(trip_miles)`、Y = `AVG(trip_total)`」のように 4 つの変数を同時に可視化できます。

::: warning データ量と描画
散布図はマーク数が多くなりがちです。100 万行をそのまま打点すると重く・読みづらくなるので、**フィルターで件数を絞る** か **粒度を粗くする**（例: `pickup_community_area` 単位）必要があります。
:::

## 5. 円グラフ・ツリーマップ

**構成比** を見せるチャートですが、それぞれ得意な場面が違います。

| チャート | 強み | 弱み |
|---------|------|------|
| **円グラフ** | 2〜3 カテゴリの大小直感的 | カテゴリが多いと判別困難 |
| **ツリーマップ** | カテゴリが多くてもサイズで比較可能 | 厳密な値比較は棒に劣る |

### 作り方

- **円**: マークタイプを「円グラフ」に。**角度** シェルフに `SUM(trip_total)`、**色** に `payment_type`
- **ツリーマップ**: マークタイプを「四角」に。**サイズ** に `SUM(trip_total)`、**色** か **詳細** に `company`

::: info 円グラフは多用しない
データ可視化の一般論として、円グラフはカテゴリが 4 つ以上になると棒グラフに劣ります。本気で構成を伝えるなら **横棒 + 100% 積み上げ** のほうが多くの場合読みやすくなります。
:::

## 6. ヒートマップ・ハイライトテーブル

セルの色で大小を表すチャートです。**2 つのディメンションの交差** を一覧したい場合に効果的です。

| チャート | マークタイプ | 用途 |
|---------|-----------|------|
| **ヒートマップ** | 四角 + サイズ + 色 | 件数と金額のような 2 メジャーを同時に |
| **ハイライトテーブル** | 自動 + 色 | テキスト値もそのまま見せたい |

例: 列に `DATEPART('hour', trip_start_timestamp)`、行に `DATENAME('weekday', trip_start_timestamp)`、色に `COUNTD(trip_id)` を置くと、「曜日 × 時間帯の需要ヒートマップ」が作れます。

## 7. 地図（記号マップ / 塗り分けマップ）

Chicago Taxi には緯度経度 (`pickup_centroid_latitude` / `pickup_centroid_longitude`) があるので、地図表現が自然に作れます。

### 記号マップ（Symbol Map）

緯度経度の点を地図上に打つ方法です。

1. `pickup_centroid_latitude` / `pickup_centroid_longitude` の地理的役割を緯度・経度に設定（02 章参照）
2. ダブルクリックで自動的に列・行に展開され、地図が出現
3. **詳細** に `pickup_community_area` を入れて粒度を確保
4. **色** に `SUM(trip_total)`、**サイズ** に `COUNTD(trip_id)` などで意味を持たせる

### 塗り分けマップ（Choropleth）

エリア (community area) などの **形状** で塗り分けるマップです。標準で Chicago のコミュニティエリアの形状が含まれていない場合があるため、Shapefile / GeoJSON を別途読み込んで結合する手順が必要になることがあります。

::: info マップタイルとオフライン
地図の背景タイルは Tableau がインターネット経由で取得します。完全オフライン環境では背景が出ないため、社内ネットワーク要件を事前に確認しましょう。
:::

## 8. 二重軸・複合軸（シンクロ軸）

1 つのビューに **複数のメジャー** を重ねたいときに使います。よく混同される 2 つを区別しましょう。

| 種類 | 特徴 | 軸の数 |
|------|------|--------|
| **二重軸 (Dual Axis)** | 左右で **別々の軸** を持つ | 2 本（左右独立） |
| **複合軸 (Measure Names / Values)** | 1 本の軸を **共有** | 1 本 |
| **シンクロ軸** | 二重軸の左右を **同じ尺度** に揃える | 2 本（同期） |

### 二重軸の作り方

1. 列または行に **2 つ目のメジャー** をドラッグ
2. 2 つ目のメジャーピルを右クリック → 「二重軸」
3. 必要に応じて、片方のマークタイプを変更（例: 1 つ目は棒、2 つ目は線）
4. 単位が同じ場合は、軸を右クリック → 「軸の同期」で **シンクロ軸** に

### Chicago Taxi での例

- 月別の `SUM(trip_total)`（棒）と `AVG(trip_miles)`（線）を二重軸で重ねる
- 単位が違う（USD と マイル）ので、シンクロ軸ではなく **二重軸のまま** 使う

::: warning 二重軸はミスリードに注意
左右の軸が独立しているため、目盛りの取り方ひとつで「相関しているように見える」「逆相関に見える」など印象を操作できてしまいます。共有する場合は軸の起点と単位を明示しましょう。
:::

## 9. Show Me パネルとマークタイプ手動切替

### Show Me パネル

画面右上の **「Show Me」** ボタンを押すと、現在ビューに置かれているフィールドから **作成可能なチャート一覧** が表示されます。

- 推奨されないチャートは **グレーアウト** されます
- マウスを乗せると「あと何が必要か」（例: 1 つ以上のディメンション、1 つ以上の日付）がツールチップで分かります
- 学習段階では便利ですが、自動配置されたシェルフを後で **手で調整** する前提で使うのが現実的です

### マークタイプの手動切替

Show Me に頼らず、マークカード一番上のドロップダウンから手動で **棒・線・円・形状・四角・テキスト・地図・パイ・密度** などに切り替えるほうが、慣れてくると速い場面が多いです。

| マークタイプ | 主な用途 |
|------------|--------|
| 自動 | Tableau に任せる |
| 棒 | 比較 |
| 線 | 推移 |
| エリア | 推移 + 構成 |
| 円 | 散布図のマーク |
| 四角 | ヒートマップ |
| 形状 | カスタム形状 |
| テキスト | クロス集計表 |
| マップ | 塗り分けマップ |
| 円グラフ | 構成 |
| 密度 | 大量点の濃淡可視化 |

## やってみよう

`chicago_taxi_trips.hyper` で、6 つの目的軸を一通り作ってみましょう。

1. **比較: 会社別売上の横棒**
   - 行に `company`、列に `SUM(trip_total)` → 軸ヘッダーで降順ソート
2. **推移: 月別売上の折れ線**
   - 列に `trip_start_timestamp`（連続 / 月）、行に `SUM(trip_total)`
3. **分布: 距離のヒストグラム**
   - データペインで `trip_miles` を右クリック → 「作成」 → 「ビン」 → サイズ 1 (マイル)
   - 列にビン化した `trip_miles (bin)`、行に `COUNTD(trip_id)`
4. **構成: 支払方法のツリーマップ**
   - マークタイプを「四角」に。サイズに `SUM(trip_total)`、色と詳細に `payment_type`
5. **関係: 距離 × 料金の散布図**
   - 列に `SUM(trip_miles)`、行に `SUM(trip_total)`、詳細に `taxi_id`
   - アナリティクスペインから「トレンドライン」をドラッグ
6. **地理: 乗車地の記号マップ**
   - `pickup_centroid_latitude` / `pickup_centroid_longitude` の地理的役割を確認
   - 両フィールドをダブルクリック → 詳細に `pickup_community_area` → 色に `SUM(trip_total)`
7. **二重軸: 月別売上（棒）と平均距離（線）**
   - 列に月、行に `SUM(trip_total)`（棒） → 行にさらに `AVG(trip_miles)`（線） → 「二重軸」
8. **Show Me パネルの動作確認**
   - Show Me を開き、現在のフィールド構成でどのチャートが提案されるか確認

## まとめ

- チャート選定は **比較 / 推移 / 分布 / 構成 / 関係 / 地理** の目的軸から逆算します。
- 棒・折れ線・散布図・円/ツリーマップ・ヒートマップ・地図の **基本 6 種** が業務の大半をカバーします。
- 日付フィールドは **不連続 (年/月のヘッダー)** か **連続 (時間軸)** かで挙動が大きく変わります。
- **二重軸** は左右独立、**シンクロ軸** は同期、**複合軸** は軸を共有します。用途で使い分けます。
- **Show Me** は学習補助として便利ですが、最終的には **マークタイプを手動で選ぶ** ほうが自由度が高くなります。
